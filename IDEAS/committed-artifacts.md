# Idea — Committed artifacts: the derived file as a gate

**Status: the family is BUILT; two members are unbuilt and one shape is rejected.**
Dated 2026-08-14. Seven generators, thirteen committed files and one shared runner
shipped this day — read `packages/*/CHANGES.md` for what each does, and
`packages/cli/core/snapshots.js` for the engine. Do not cite the § Candidates
section below as behavior: nothing there exists.

This file exists because the *rule* the family follows was argued in a session and
recorded nowhere, so the next person proposing an artifact would re-derive it — and
the two that were considered and declined would come back as ideas without their
reasons attached.

---

## The one-line verdict

A snapshot earns its place when the thing it records **has no other way to be
wrong loudly**: not when it would be nice to see, and not when a test already
fails. Everything else about the design follows from keeping the diff readable
enough that somebody actually reads it on the commit that matters.

## The rule, stated once

Six properties, each of which was a decision and not an accident.

**1. Derived from the owner, never re-derived.** Every generator asks the module
that already owns the fact — `deriveAccess()`, `generateDDL()`,
`generateJsonSchema()`, `svc.describe()` + `buildRoutes()`, `toFrameworkError()`
itself, the scanner, `bun pm pack`. A generator that reimplements the rule is a
second opinion, and the two disagree exactly when it matters. `FJS-254` is the
worked case: `extractServiceMeta` was deleted rather than kept as a fallback, and
`fli project:map` reports no services at all where there is no snapshot.

**2. Executed where executing is possible.** `errors.snapshot.md` throws real
values through the real boundary; `surface.snapshot.md` reads a BUILT app rather
than source text. A table written from the source says what someone believes.

**3. Human-readable, at a granularity that does not churn.** `exports` records
top-level entries and no versions, sizes or file counts, because a snapshot that
moves on every commit is regenerated without being read — the failure mode is not
a wrong file, it is an ignored one. The JSON Schema snapshot is markdown for the
same reason: the raw document is thousands of lines and a removed keyword hides
in it.

**4. Each file names its own generator.** `generated by: <command>` in the header,
in whatever comment syntax the format has. That is what lets one runner check all
of them without a registry, and it is also what makes the file self-explaining to
a reviewer who has never run the command.

**5. The runner is shared, and the header is untrusted.** `core/snapshots.js`, two
callers (`fli test:snapshots`, `scripts/ci.mjs`) for the reason `core/checks.js`
has two. The command comes out of a file in the repository and the runner executes
it, so the binary must be one of four framework CLIs and every argument a plain
flag or path.

**6. Fail closed in both directions.** Stale is a failure; so is *gone*. Discovery
alone reports one fewer snapshot in green, which is the same shape as a package
with no `test` script — the first thing `ci.mjs` exists to refuse. The removal
check compares against the base ref, so adding still costs nothing and removing
costs a named allowance.

## Candidates — argued, not built

### A. A Mesa golden compile corpus

**What breaks silently.** Invariant 12 says compiler output is reproducible
because scope ids are content-addressed, and that is what makes CSS dedupe work
across the two compilers a static build runs. Nothing asserts it. Invariant 15's
tests *parse* compiler output; they do not compare it. So a change to the hashing
input — a whitespace normalization, a different serialization of the AST — leaves
every suite green and silently doubles the CSS a prerendered page ships, or
worse, dedupes two rules that were not the same.

**Shape.** A small curated fixture set (perhaps 10–15 `.mesa` files, each chosen
for one feature: scoped style, `:global`, `{#each}`, `{@attach}`, an island, a
`<script module>`) compiled to committed output. Normalized whitespace. A second
section recording just the scope ids, because that is the part with the
cross-compiler contract.

**Why it is not built.** Two real objections. The diff is noisy in a way the other
seven are not — a compiler change legitimately rewrites every file, so the signal
(*ids moved*) drowns in the noise (*output moved*). And a golden corpus tends to
be regenerated reflexively, which converts it from a gate into a formality. The
narrow version — **ids only, not output** — probably survives both objections and
is the version to build first.

**Effort:** S for the ids-only form, M for full output.

### B. The UI kit contract

**What breaks silently.** Three rules currently live in prose:
`@frontierjs/ui` may not style a class `@frontierjs/css` owns; every component
forwards its caller's attributes; where that spread lands is not uniform (a form
control puts it on the CONTROL, because that is what a `<label for>` and an
`aria-describedby` must reach). All three are invisible when broken — the
component still renders.

**Shape.** One row per component: declared props, where the attribute spread
lands, which `@frontierjs/css` classes it uses, whether it declares tokens of its
own. Generated by compiling each component, so it is derived rather than read.
The tokens column would make `FJS-128`/`FJS-129` a number that moves rather than a
paragraph — `DatePicker` and `CommandPalette` carry 69% of the kit's CSS in their
own scales.

**Why it is not built.** The kit is the least settled surface in the repo (29 of
64 verified in a browser), and a snapshot over a moving surface is a file that is
regenerated on every commit — see property 3. Worth doing when the component set
stops moving, and the tokens column is worth pulling out *now* as its own smaller
artifact if `FJS-128` is being worked.

**Effort:** M.

## Rejected

**A deployment artifact.** `make:deploy` writes a Dockerfile and a compose file,
and snapshotting them looks like the same idea. It is not: the `deploy` CI phase
builds the image and asks it for a health answer, which is strictly stronger than
comparing the text that produced it. A snapshot here would be a second, weaker
check that people would then trust.

**A registry of expected snapshots.** The obvious answer to *discovery fails
open* is a list in `ci-allowances.json`. It closes the hole and reintroduces the
cost the header was designed to remove — a new kind of snapshot would need a CI
edit again, and a list nobody updates is its own drift. The base-ref comparison
answers the same question from evidence rather than from a declaration.

**Versions, sizes and file counts in `exports.snapshot.md`.** Each is real
information and each moves for reasons nobody wants to review: a release bumps
sixteen versions at once, and any source edit moves a size. The file would be
correct and unread.
