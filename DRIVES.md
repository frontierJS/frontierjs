# Drives

**What proves a change here, and what to start before proving it.** A drive is a script that runs an app or a package end to end — a real server, a real database, usually a real browser — and asserts on what a person or a caller would see. The package's own suite is always first; this file answers *and then which drive*.

**Most turns should not read this file top to bottom.** `fli proves` reads both tables against your diff and names the drives it needs; `fli gui` shows the same answer with a start button per drive. Read on when a row needs its reasoning, or when you are adding one.

**Both tables are parsed, so a header here is an interface.** `packages/cli/core/proofs.js` owns this file's path. **A new drive gets a row in each table** — `fli check`'s `proof-drive-named` reports a drive the second one does not name.

## The drives

**Some drives need servers started first, and the *Start first* cell says which.** A drive whose server is missing exits 1 naming it. The browser drives need Chrome. **The *Start first* column is READ** — `packages/cli/core/preflight.js` parses it, `runnables.js` puts the resolved steps on the drive's row, and `fli gui` walks them behind one button, skipping anything already answering. So the order in a cell is the order they are run in, `nothing` is the explicit empty answer rather than a blank, prose after the em-dash is not read, and a step whose script has been renamed is a `fli check` error (`drive-preamble`) rather than advice somebody notices is wrong. What it cannot see is the drive's own check, which is the half `--preflight` would close.
