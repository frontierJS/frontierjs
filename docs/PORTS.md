# Ports

`packages/cli/core/ports.js` is the schema, and `fli ws:atlas --as=report` renders the id table from it. This file is the reasoning and the per-drive exceptions the schema cannot carry.

**Ports.** `port = env*1000 + category*100 + project*10 + service`. `packages/cli/core/ports.js` is the schema — the formula, the category map, and the `PROJECTS` registry. env: 7 test · 8 dev · 9 prod. category: 0 fe · 1 be · 2 widgetDev · 3 widgetServe · 4 ext · 5 tooling · 6 siteDev · 7 siteServe · 8 desktopDev. `packages/jetty/src/dev/fjs-ports.js` owns the extension slice (8400–8499 dev, 7400–7499 test).

The widget and site columns are why categories 2, 3, 6 and 7 exist: a surface that is both WRITTEN against and SERVED as its own origin needs two slots, and both `widgets/` and `site/` are that shape — a server while one is being written, a static origin once it is served, and neither is the SPA's. They are CATEGORIES rather than service digits on the `fe` row because the served half is not the SPA's second server, which is the one thing it is not. **The tooling block is the exception and is reserved whole**: 8500–8509 is dev/tooling/project-0, refused by the formula for every slot rather than for the ones currently assigned — a tool there is one somebody runs beside whatever app they are working on and types from memory, so it can neither take a number from the app's row nor be handed one at runtime. The numbers are derived, not chosen: an app of this repo takes the next project id, and all ten are assigned. **Every other app is project 0 and shares it by service digit** — `fli dev` claims a slot per app root in `~/.fli/sessions.lock`, remembered so the app comes back on the same ports, and hands it to the servers it starts as `FLI_PORT_*`; an app whose configs do not read them stays at 0 (`packages/cli/core/ports.js` § Dev slots). **Every surface also has a NAME, derived from the same table**: `example.localhost` is 8010 and `api.example.localhost` is 8110 — the frontend takes the bare label, every other surface is a subdomain of it, and tools are under `fli.localhost`; `fli check`'s `dev-host-unique` refuses two packages whose names reduce to one label, which is `strictPort`'s failure one layer up. `fli proxy` maps Host to port (`packages/cli/core/proxy.js`); it wants 80 and falls back to 8504, and it is a TCP proxy because bun's `node:http` emits `upgrade` and hands over a socket nothing written to ever reaches the client, which would make junction's live layer and vite's HMR load and then silently stop. Nothing is rewritten — junction READS the Host and vite allows `*.localhost` — and the target is picked per CONNECTION, which no client that derives its Host from its URL can reach. **Strictly additive: every number keeps working and nothing may come to depend on a name.** **Every vite config sets `strictPort`** — vite otherwise hops to the next free port in silence, and the second app's drive tests the first app's app. A scaffolded app reads `FLI_PORT_FE`/`FLI_PORT_BE` when `fli dev` set them; the literal is only the static default.
