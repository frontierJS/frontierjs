# Routes, prerender and static

The full entries behind this section of the `ui-hazards` skill's index.

- **The route table is a naming convention over a file tree, so it is committed too.** `sierra routes --config config/sierra.config.js`, run from the app's **web root**, writes `routes.snapshot.md` — every URL with its file, the layout the scanner resolved (none where a page declared `reset`), the meta a layout pushed down onto every page under it, and what each `_module.mesa` wraps. On a `static` target **`publishes:` leads the file** in its own section, since that one line in one page's frontmatter is what lets a gated model's columns into a public file — it names them per model (`FJS-D496`), and a column read outside it fails the build. One config is one target and its name carries — `sierra.static.config.js` → `routes.static.snapshot.md`. The `snapshots` CI phase fails a stale one. Ruled: `FJS-D464`.
- **A component rendered at BUILD time may import a sibling by relative path, and that had never worked.** `renderComponent` writes the compiled module to a temp directory, so a relative specifier is rewritten to an absolute PATH — not a `file://` URL, which Node takes and Vite's import-analysis refuses (`FJS-438`). Bare and absolute specifiers pass through as written.
- **On a static target, dev is an SPA and the build is files, and only the build checks anything.** A `render: static` route's `load()` runs in Node at build time, and its companion may never enter the browser graph (`FJS-543`). On the dev server, `/__sierra/static-data` executes the loader and the browser gets JSON: the route table emits a **fetch shim and never an import**, which keeps `FJS-543` closed. The loader is imported the way the BUILD imports it — a plain `import()` keyed on mtime, not `ssrLoadModule`, which rewrites the module and withholds Bun's `import.meta.dir` — so the dev server must run as `bun --bun vite`, as `build:site` does. `dev: { staticData: false }` turns the endpoint off, and every prerendered page then renders `data: null`. A route on a static target that is NOT prerendered keeps its loader and runs it in the browser like any client-routed page. `target: 'static'` is the SPA's Vite config plus a prerender pass in `closeBundle`, so dev serves the routes client-routed, and the publish check, the island chunks, one HTML file per route and the refusal when a `render: static` route emitted nothing all live in the build. **A page that works in dev and fails in the build is the normal case.** **A companion is build-time only and the static build says so**: its loaders are dropped from the client route table, because rolldown otherwise follows every `.meta.js` into the browser graph and publishes what it imports — the app's own Litestone client, the DDL emitter, the migration engine — as fetchable files on a public origin. Ruled: `FJS-D463`.
- **A static route that produced no page fails the build where it was broken, and warns where it opted out.** *Not found* and *no paths* are a page opting out and warn; `load()` threw and *render failed* are a broken build and throw naming the route (`FJS-439`). Keep the two on separate paths: one shared warning list buries a broken build among the bundler's own lines and exits 0.
- **A server render answers every browser global as a wide desktop, so only a mobile-first branch bakes correctly** (`FJS-D214`). happy-dom answers `innerWidth` 1280, `matchMedia(…).matches` false for every query and a Node user agent, and `localStorage` is absent and throws. A component branching on width bakes the desktop branch into the static page, one branching on a media query bakes the false branch, and nothing warns — silence is the ruling, because a per-read warning fires on every page of a prerender. Write the branch so the server answer is the safe one, move it behind `$.onMount`, or make it an island. The table is `packages/mesa/docs/STATIC_RENDERING.md` § What a browser global answers.
- **`renderComponent` reuses a compiled tree, so `<script module>` state is shared across every render in the process** (`FJS-1659`). The tree is cached per entry, source and options and re-hashed before reuse, which is what stopped email-kit and Transit's reports from growing RSS by a module per render. A module-level variable is therefore one value for every email, PDF and prerendered page the process makes, as it is for every instance on one browser page. Per-render data goes in props.
