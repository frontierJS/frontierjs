# Resources and forms

The full entries behind this section of the `ui-hazards` skill's index.

- **A write drops the columns the SERVER owns, and the version column is the one exception.** `@system`, `@generated`, `@computed`, `@from`, `@version` and a tenancy stamp all reach the client as `readOnly`. A create is safe because `make()` never seeds one; an EDIT form is handed a row the server wrote and sends the whole thing back, and the Data boundary refuses `@system` BY NAME — a 403 about a column not on the person's screen (`FJS-526`). `stripReadOnly` runs first in the resource's create/patch pipeline, ahead of coerce, blank and validate, so nothing judges a value that will not be sent. It takes a KEEP list rather than dropping everything read-only, because `@version` is read-only and the server requires it back. A key with no field rule behind it is left alone, because a `@transient` is legitimate there. Ruled: `FJS-D462`.
- **A `File` column's control sends the bytes WITH the record, and there is no upload step.** A `File` anywhere in a payload turns the create or patch into `multipart/form-data` at the client, the bridge merges it back into `ctx.data`, and `FileStorage` stores it — so submitting the form IS the upload, on the one route carrying the gate, the row policies and `@accept` (`FJS-409`, `FJS-D260`). Until then the field holds the browser `File` itself, which the resource's write pipeline passes through untouched. **The value has three shapes and only one of them is ever sent**: `undefined` where nothing is set, the URL a READ resolved the stored reference into, or the `File` just chosen. `undefined` back from the control means *leave the stored file alone* and `null` means *clear the column*; a form that conflates them drops the stored file on every edit that did not touch it.
- **`createResource` coerces, blank-strips and validates by default.** A bad create throws `ResourceValidationError` in the browser without making the request, and an untouched text box writes NULL rather than `''`. A resource whose service accepts a shape the model does not describe needs `{ validate: false }`; otherwise the symptom is "the button does nothing" unless something renders the throw. `<Form>` renders it.
- **`@system` is the column an application writes and its caller does not** — readable by anyone, refused on write by name; `@guarded` is the sibling that locks both directions (`FJS-D22`). It reaches the client as `readOnly`, so a generated form does not offer it and `make()` does not seed it, and it is **out of create-mode `required`**, or every create in the browser is refused naming fields the caller was never meant to send (`FJS-095`). The app fills it by naming the column on the write — `db.order.update({ where, data, system: ['trackingCode'] })` — which keeps the gate, the row policies and the audit actor that `asSystem()` drops. A required `@system` column nobody filled fails at the write, saying which side is missing.
- **`<Form {resource} />` with no children IS the form** — every writable column in schema order, each with the control its type implies, over the one table in `field-rules.js`. Children win; `only` narrows and orders, `except` removes, `auto` forces either way. **Only DEFAULT children turn generation off** — `_auto` is `auto ?? !$slots.default` — so `slot="actions"` composes with the generated list, which is how a Resource's own default form supplies a button row (Invariant 18, `FJS-D112`). A `{#snippet actions()}` beats the slot where both are given, as the more specific statement. A column the table cannot place is **warned about by name** rather than dropped. **The shape to beware is an `{#if}` around a `slot=` child**: `slot=` is an attribute on an ELEMENT, so the BLOCK is default content, `$slots.default` is truthy, and the form renders with no controls in it (`FJS-607`). A form that generated nothing AND holds no control, over a resource with fields to offer, warns naming them — checked in the DOM at mount, since children arrive as opaque content. Render the `slot=` elements unconditionally, as every resource file here does.
