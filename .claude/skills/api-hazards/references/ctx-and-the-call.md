# `ctx` and the call

The full entries behind this section of the `api-hazards` skill's index.

- **`ctx.params` does not exist anywhere in Junction, and `ctx.route` is not it.** A `ServiceContext` splits into `auth` (the principal) / `client` (`ip`, `userAgent`, `headers`) / `route` (path captures alone) / `locals` (per-call scratch, where `withLitestoneDb` puts `db`); a `TransportContext` carries the same `route` and puts headers at `ctx.headers`. The four follow four different rules: `auth` is frozen and PROPAGATES to a nested call at any depth, `client` propagates, `route` is router-only (`{}` internally), `locals` is fresh per call and does NOT propagate. `packages/junction/CLAUDE.md` § The two contexts is the reference and `test/context-contract.test.ts` runs it. Reading `ctx.params.user` (a Feathers idiom) yields `undefined`, so a role check on it passes for everyone. Also: `before: { all: [...] }` applies to every method, machine-facing endpoints included.
- **Absent is not null on `auth`.** A call naming no `auth` inherits the principal in scope; `{ auth: { user: null } }` means *as nobody* and stays anonymous. It is the only way to ask what a stranger would see.
- **A payload key that is not a column is declared `@transient`, and it arrives at `ctx.transients` — never at `ctx.data`.** No column, written by the caller, never read back (`FJS-D23`). `autoValidate` validates it with the model's own rules and then LIFTS it off the payload, because the Data boundary refuses a transient key by name — a service passing `ctx.data` on whole fails the write rather than the field. Fresh `{}` per call, does not propagate, `{}` on a model that declares none. **A bulk write carrying one is refused**: the rows a service receives are the ones that passed validation, so an index-aligned array would pair one row's value with another row. An undeclared key that is not a column is refused (`FJS-889`), and the refusal names `@transient` as the fix.
- **A payload key that names no field of the model is a 400; one that names a field the caller may not WRITE is dropped in silence** (`FJS-889`). The strip is mass-assignment protection for fields that exist but are not writable — `id` on a create, `createdAt`, a `@guarded` column — which a client PUTting back a row it fetched sends on every write. An unknown key is refused because dropping it turns a typo (`{title, titel: 'typo'}`) into a 201 the caller believes in. The set is read off `$schema.models` and **not** off the generated documents, because `createdAt` and `updatedAt` are in no document `create`/`update`/`read` emits, and a document-derived set would refuse the commonest legitimate echo. Checked **per row**, so a bulk write still partitions. A declared `input:` type is the same rule against its own properties. **The escape is `@transient`** and the refusal names it; there is no *did you mean*, because litestone owns the typo hint. Ruled: `FJS-D437`.
- **`PUT` to an id that does not exist is 404 and does not create the row** (`FJS-D207`). A caller-supplied `String @id` answers 404 exactly as a server-assigned `Int @id` does. Creating a row at a chosen key is `POST` carrying the id.
- **`update` is `patch` with an id REQUIRED, and it MERGES** (`FJS-D179`). The write is litestone's `table.update`, so a `PUT` stating only `title` leaves every column it did not name where it was. The required id keeps a REST client's `PUT` off patch's query path, which is a bulk write. It must not be validated against the CREATE-mode schema, which omits `@version` and so strips the version a versioned model's write requires (`FJS-663`).
- **The METHOD decides list vs single.** `find` must answer a list or it throws `ResultShapeError`; an array is a list; the bulk `{data,errors}` protocol is a list on any method; everything else is a single and travels whole. A service answering one thing names it and calls it as a custom method; a summary alongside rows is its own named method.
