# Jobs and the clock

The full entries behind this section of the `api-hazards` skill's index.

- **Caravan owns the clock; `app.scheduler` is in-process only** (`FJS-D36`). Two timers exist and they are not the same feature — `app.scheduler` has no persistence, no retry and no principal, and is gone with the process; `app.jobs` is durable work. **A timer that dispatches into a queue is the QUEUE's schedule**, registered with `app.jobs.schedule(name, expr, fn)`; firing `app.jobs.dispatch(…)` off `app.scheduler` gets none of the queue's durability. **Caravan's clock is safe to run in two processes and junction's is not** — a cron fire is dispatched under `cron:<job>:<epoch-minute>`, so a second replica's fire is a no-op rather than a second row, and a `running` row is owned by a heartbeating instance so recovery reclaims only what a crashed one left (`FJS-294`). A schedule that came from a database ROW also needs `app.jobs.unschedule(name)` when the row stops being true, and re-registering at boot — neither registry survives a restart. `app.scheduler` is for work with no row behind it: a cache sweep, a metrics tick.
- **A background job runs as whoever asked for it, and a job nobody asked for runs as the app.** Caravan records the principal in scope at `dispatch()` and Junction re-resolves them when the job runs (`app.runAs`), so `ctx.app.service('x').patch(…)` from a handler names no `auth` and inherits one. **An id is stored, never a session** — a caller demoted between asking and running is graded at the standing they hold now (`FJS-D69`). No enqueuer (a cron fire, boot) resolves to `createApp({ system })`, the one place an app says who it is acting on its own behalf; declaring none is valid and gives `null`. `example/api/src/core/gate.ts` is the pattern. `db.asSystem()` is the wrong fix: it writes at the Data boundary where nothing announces, so every open tab keeps the stale row.
- **A job attempt has no bound unless one is declared, and `oldestRunningMs` is how you see the ones that do not.** `timeout` on a handler, a job file or a queue; absent means no bound, because a default would kill every legitimately long job. A timeout is an ordinary failure — it counts as an attempt and retries on the same ladder as a throw — and **it does not stop the handler**, since nothing in JavaScript cancels a promise: the abandoned invocation may still be writing while the retry runs, so it is announced (`caravan.job.orphan`). A handler that never yields is unreachable either way; the timer needs the event loop. For the jobs nobody bounded, `stats().queues.<q>.oldestRunningMs` separates a stalled queue from a busy one — `running: 1` reads identically for both — and it is asked of the database, so another replica's stuck job is in the answer (`FJS-295`). `drainTimeout` bounds `stop()`. Ruled: `FJS-D438`.
- **Caravan's `unique` is a lock on work IN FLIGHT, not an idempotency key.** Once a job is terminal the key is free. A key built from a row id is not one either — SQLite reuses ids.
- **A job in `jobsDir` is named by its file and declares its own schedule.** `send-email.job.ts` is `send-email`; a `defineJob` naming anything else is refused at load, since a handler registered under a misspelled name is a dispatch that silently never runs. `cron` is a `handle()` option — a `*.job.ts` file carrying one is scheduled by being autoloaded, and `schedule()` is sugar over the same registration. The definition is also the dispatch handle: `dispatch(sendEmail, data)` states no name and types the payload. **The queue's database opens on first use**, which is what lets every key of `junction.config.js`'s caravan section apply — and means a dispatch before `app.configure(…)` opens it at the DEFAULT path.

- **A cache value is JSON, and what JSON would LOSE is refused at `set()`.** One codec serves both drivers, so what is storable is one answer, and it is what a Litestone row, a response body and a WS frame already carry (a `DateTime` reads back an ISO string). A `Date`, a `Map`, a `Set`, a `RegExp`, a `BigInt`, `NaN` and a typed array throw naming the key and the way out, at any depth, because each of them serializes and comes back as something else (`FJS-898`). Top-level `undefined` is refused for a second reason: `get()` answers it for a miss. **The memory driver holds the value encoded**, so `get()` hands back a fresh value and mutating it reaches nothing; a cached live reference is a semantics no persistent backend can offer, so code written against it would break when the driver is swapped. `clear(string)` is a PREFIX match in both; eviction is LRU with `get()` a use and `has()` not one. Anything new here is asserted in `test/cache-conformance.test.ts`, which runs ONE body against both drivers — a test per driver cannot see a divergence. Ruled: `FJS-D439`.

- **`/health` is READINESS and `/health/live` is LIVENESS, and a draining process answers them oppositely.** An orchestrator RESTARTS a process that fails liveness and stops sending traffic to one that fails readiness, so a third-party dependency going down belongs on `/health` and never on `/health/live` (`FJS-901`). Liveness consults nothing, including the drain: killing a draining process destroys the in-flight requests the drain exists to finish. Every check is bounded by `checkTimeout` (2000ms) and they run CONCURRENTLY; a timed-out check is a `fail` row naming itself, since nothing cancels it. A check is entered through `Promise.resolve().then(fn)`: calling `fn()` lets a SYNCHRONOUS throw escape its own promise and reject the whole collection, a 500 naming no check. Ruled: `FJS-D440`.
- **`/metrics` answers exposition text to a caller whose `Accept` asks for it, and JSON to everyone else.** The path is a Prometheus convention, so a scraper gets its format; a browser leads with `text/html` and curl sends the wildcard, so the devtools console and `fli gui` keep the JSON they read. One collector, two renderings. **A number is a metric and nothing else is**: a string, an array and a boolean are skipped rather than counted, which also bounds cardinality, since a `registerMetricsSource` section of names and flags emits no series. No `# TYPE` — a counter is not tellable from a gauge by name. Ruled: `FJS-D441`.

- **The OpenAPI spec is graded by CALLING what it documents, and a custom method is not a path.** CRUD verbs are emitted only where `methods:` allows them, and there is no `/{service}/{id}/{method}` route — the wire dispatches `POST /{service}/{id}` on `X-Service-Method` (`FJS-902`). So custom methods are ONE operation with the allow-list as a header enum and a `oneOf` body, because OpenAPI dispatches on path and verb and cannot express a different operation per header value (`FJS-D218`). What a service answers comes from `describe().methods` (policy applied), and a path with no operations left is not emitted. Add to `test/openapi-round-trip.test.ts`, which calls every operation against the app that produced the spec — a per-clause test passes on drift nobody predicted.
- **The docs page is hand-written HTML with two caller-supplied values in it.** The title goes into markup and the Scalar config goes inside a `<script>`, so a `customCss` carrying `</script>` can close the element. Grade it by counting the elements a PARSER finds; a substring check on the injected text reads as correct. The CDN reference is PINNED, because unpinned it runs whatever that package published today on the API's own origin; the pin going stale is the cost. Ruled: `FJS-D442`.

- **A battery names a vendor in a comment and never in a call** (`FJS-D215`). Junction keeps the SHAPE — `IAIModel`, `AIBuilder`, `AIRegistry` — and an app's adapter reaches its vendor through `app.conduit`, where a timeout, a retry, a breaker, an auth header and a body encoding are declared per TARGET rather than restated per provider. A first-party connector lives in its own package with its own sink (`FJS-D153`).

- **Nothing here mocks a module, and the reason is a design rule.** `mock.module()` is applied PROCESS-WIDE by bun and never undone, so one file mocking a transport makes every later file in the run grade the mock (`FJS-908`). What a test needs instead is an **injected transport**: `createSystemSender(config, { transport })`, Outpost's runner one package over. A double for the mail interface itself is `createTestMailer()` in `@frontierjs/testing`, and it applies the SAME address and header guards the real path does — a double that accepts a message SMTP would reject passes the test and fails in production. There is no cache or storage double: `createMemoryCache()` and `FileStorage({ provider: 'local' })` already ARE those, and a second would drift. Ruled: `FJS-D443`.

- **A test may not name a port, and the reason is the runner.** Bun runs every file in ONE process and an app's `stop()` does not finish before the next file's `start()` begins, so two files on one port means a socket is answered by the other file's app mid-shutdown — its `Server shutting down` reaches the client as `Expected 101 status code`, which reads as whatever assertion was nearest (`FJS-900`). Ask for `port: 0` and read the bound port back after `start()`, which is what `@frontierjs/testing`'s `listen: true` already does.
