# Routes, query and headers

The full entries behind this section of the `api-hazards` skill's index.

- **A query string is PARSED, and the schema still wins.** `?qty=5&live=true&qty[gte]=3` reaches a service as numbers, booleans and structure — `@frontierjs/toolbelt/query`, one module for junction's transport, junction's client and sierra's router, so HTTP and the socket filter identically (`FJS-D125`, `FJS-450`). **A string is a number only if it round-trips** — `'007'`, `'+1'`, `'1.50'`, `'1e5'` and a snowflake id all stay text — and `?code="5"` is the escape for the rest. **Where a model exists it has the last word**: `id String` filtered by `?id=5` reads 5 and Litestone converts it back to `'5'`.
- **Raw routes (`app.get`/`app.post`) take `{id}`, not `:id`** — `:id` registers as a literal segment and answers 405 forever, never matching a real request (`FJS-1024`, open).
- **`apiPrefix` moves EVERY route the app registers**, auth's `/auth/login` and caravan's `/jobs` included, because the `app.get`/`app.post` shortcuts are its one owner. A path that must not move is registered on `app.http.router` directly. An app that sets a prefix proxies one path, not one per plugin. A prefix stated only in `junction.config.js` reaches the routes at `load-config`, which moves every route registered before it, so a path read inside `register()` still carries `createApp`'s prefix — read mounted paths from `boot()` (`FJS-3072`).
- **Every READ carries `$withDeleted`; on a WRITE only `update`/`patch` by id do.** That is the escape hatch a `SoftDeletedUniqueError` points at — a deleted row keeps its `@unique` values (`FJS-D65`), so *move the value aside* is `PATCH /{service}/{id}?$withDeleted=true`, and without it no request an app can make frees the slot. The default is fail-closed: the same request with no directive is a 404. **A bulk patch does not read it** — `bulkByRow` selects its targets through litestone's own filter, so a widened WHERE would match nothing. **`remove` declines it by NAME**, not as a 404: against an already-deleted row the only action left is to destroy it, the one write that defeats `@@softDelete`, and the directive on an ordinary DELETE would hand that to every caller who may remove a row with no separate permission to grade. Graded on the REQUEST rather than the row's state, and silent on a model that hides nothing (`FJS-523`). Ruled: `FJS-D448`.
- **`hasRoute()` is a matching question, not an existence one** — every app registers `GET /{service}`, which matches almost anything. Use `hasExactRoute(method, path)` for "is this mounted", `routePaths(method)` for what landed where.
- **A header the caller varies per call must be DECLARED, or it works until the socket connects.** `config.http.callHeaders: ['x-cart-token']`; the client sets it with `setCallHeader`. A WebSocket frame has no headers of its own, so the value rides `meta.headers` and the server merges only declared names — undeclared, the header is absent and whatever reads it sees nothing, which for a token-scoped row policy is an empty result with a 200 or a 404. The same declaration is what gets it past a cross-origin preflight. The identity may NOT travel this way: it belongs to the upgrade.
- **The client's address is declared, never discovered.** `X-Forwarded-For` is a list the caller can start and the shipped nginx template APPENDS to (`$proxy_add_x_forwarded_for`), so the leftmost entry is their claim and the rightmost is what nginx observed. `http.trustProxy` says how far back to believe it — `false` (the socket alone), `true` (one hop, which is what that template is), `<n>` hops, or trusted proxies by address/CIDR — and the chain is read from the RIGHT. Reading the leftmost hands the rate limiter's key to the caller; leaving it unset behind a proxy gives the whole internet one bucket (`FJS-744`). A CIDR list only works if `::ffff:10.0.0.1` is read as the v4 address it is, which is what a dual-stack listener reports. Ruled: `FJS-D449`.
- **A raw route's own `new Response(readable)` is held to its end for a caller that accepts gzip.** Every Bun Response body is a ReadableStream with no length, so a stream cannot be told from a string; only `ctx.stream()` and `ctx.sse()` mark theirs as streamed. A `text/csv` or `application/x-ndjson` stream built by hand arrives in one piece when it closes. Build it with `ctx.stream(readable, type)` or name `content-encoding` on the Response. Outside production the transport warns, once per route, when that read takes over a second (`FJS-D509`, `FJS-1427`, `FJS-1416`).
- **An API on a sibling subdomain needs no cookie `Domain`.** Measured in Chrome (`app.example.com` → `api.example.com`): a host-only `HttpOnly` session cookie set by the API rides a `credentials: 'include'` fetch from the app origin under `SameSite=Lax` and `Strict` alike, exactly as `Domain=example.com` does (`FJS-2655`). What a cross-origin page needs is `cors.origins` naming it by name plus `credentials: true` — and, in cookie mode, the same origin in `csrf.origins`, since `Sec-Fetch-Site: same-site` is refused unless the origin is listed. The boot notice says which is missing.
- **Above 128 MB, a declared length over `http.maxBodySize` is refused by Bun, not by junction** — an empty 413, no log line, before `fetch` runs. `Bun.serve`'s `maxRequestBodySize` is set to `max(maxBodySize, 128 MB)`, so under the default junction's own 413 (which names the setting) answers first; above it the runtime ceiling IS the limit, and a body that declares no length is still bounded by `parseBody` (`FJS-3090`, `FJS-751`, `test/body-limit.test.ts` § the runtime ceiling).
- **A wire `$limit` above the service's `paginate.max` is a 400 naming the max, not a clamp.** The check is in `callService`, so HTTP, WebSocket and mcp share it; an internal call still clamps through `clampPage`, and the max is the service's `paginate` (default 100), so an app whose screen reads a larger page declares the max it needs. A `paginate()` hook's own `maxLimit` stays a clamp inside it (`FJS-1972`, `FJS-D896`, `test/query-directives.test.ts` § a $limit past paginate.max).
