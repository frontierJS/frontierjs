# Bridge index — detail

The full entry for each seam the `bridge-index` skill lists. Reached from the index; the index line is the one `seams.js` parses, so an owner changes THERE.

## Schema → API/UI

- `generateJsonSchema(schema)` — consumed by junction validation and sierra's `build/schema-plugin.js` → `registerSchemas(defs, modelNames)`. **`$defs` is the whole definition table** (models, enums, `type T`, FileRef) and must stay whole — enum fields emit `{"$ref":"#/$defs/Plan"}` and both sides resolve it. Model names travel separately. Full key reference: `packages/litestone/docs/jsonschema.md`. **A keyword that stops being emitted makes a form stop validating with no build failing**, so `litestone jsonschema --snapshot` commits `db/jsonschema.snapshot.md` — `$defs`, enum values, per model the gate/relations/transitions and one row per field (type + default, required, label, keywords, which rules `x-messages` answers for), then what CREATE mode accepts — and the `snapshots` CI phase fails a stale one — `litestone/src/jsonschema.js`
- `ctx.system` — **the `@system` columns THIS CALL is supplying** (`FJS-D178`), `junction/src/core/context.ts`. A `@system` column is written by the application and refused when a caller's payload names it; litestone's hatch is `system: ['col']` on the call, which keeps the gate, the row policies, `@@softDelete` and the audit actor where `asSystem()` drops all four. A hook that DERIVES such a column declares it with `ctx.system.add('slots')`: the write happens downstream on the caller's own client, so a value placed in `ctx.data` alone is indistinguishable from one the caller sent and is refused (`FJS-644`). `systemFields(ctx)` in `core/litestone.ts` is the one reader, called at each of the five derived write args. **A Set hooks ADD to, and `readonly`**, since `before.all` and `validated.create` may each derive their own column. Naming a column widens one CALL and never the model, and an empty set is not *all*. `$.system` reads it and `$.system =` is refused by name. `@guarded` has no equivalent
- `ctx.transients` — **the `@transient` half of a payload, lifted off `ctx.data`** (`FJS-D23`). Declared in the schema, emitted `writeOnly` into the create/update JSON Schema and absent from the read modes, so a generated form offers a control for a value no read answers. `liftTransient` in junction's `autoValidate` is the one place it moves; `isStoredField` in litestone's `ddl.js` is the one answer to whether a field is a column at all — `junction/src/core/litestone.ts`
- `ServiceTypes` — **the schema's TYPES on the far side of the wire**, beside JSON Schema's rules. `litestone types --augment junction` emits `service name → row` plus the module augmentation that registers it with `@frontierjs/junction/client`, so `client.service('posts')` and `resource('posts')` infer with no type argument and an undeclared column is a compile error in the browser. Keyed by the plural through `@frontierjs/toolbelt/inflect` (Invariant 2). **Audience-split**: the API generates the system row and the browser the client row, because one shared file would tell browser code a `@guarded` column exists that every response strips. An app that generates nothing has an empty registry, which is `never`, so every call keeps the open shape — `litestone/src/tools/typegen.js` Ruled: `FJS-D454`.
- `@label` → `title`, validator messages → **`x-messages`**, keyed by rule name *and* by the JSON Schema keyword it compiles to. Litestone owns the keyword table (`jsonschema.js`); Junction's `schema.ts` and Sierra's `field-rules.js` look up the keyword they failed. A field's label is read off the field's OWN schema, never a `$ref` target — `litestone/src/jsonschema.js`
- `buildFieldRules()` / `validateAgainstFields()` / `coerceToSchema()` / `normalizeBlanks()` — `sierra/src/junction/field-rules.js`, a **leaf module** with no Junction-client import, so it runs in plain Node and is compared against junction's server rules rather than copied. Order: **coerce → blankToNull → validate**. All three on by default (`{ validate: false }` opts out; the test is `!== false`, so a threaded-through `undefined` does not disarm it)
- `controlFor(rule, {field, model})` / `formFieldList(fields, {only, except, model})` — same module, **the one place a field becomes a control**, so a generated form and a hand-written one agree about what a `Float` is. Reached through the resource (`resource.formFields()`, `resource.options(fk)`) rather than imported, because `@frontierjs/ui` peers only on mesa and css and importing sierra would invert the dependency. **A `Json` column answers `json`**, which the kit binds to `JsonInput`, with no field list under it. **It is matched on the ABSENCE of a type, not on `type: 'object'`** — litestone emits `Json` as `{}` — with two shapes carved back out: a `File` column, which `$ref`s FileRef and derefs to an ordinary object (`x-litestone-file` marks it), and a `$ref` nothing resolved, which `buildFieldRules` records as `unresolvedRef`. An array answers `json` too. A field with no control answers `control: null` **with a reason** rather than being dropped, so a new column's absence from a form is visible. **`registerControl(name, resolve)` is the way in**, and it is HALF of a contributed control: this side answers a name, `@frontierjs/ui/controls` binds that name to a component (`FJS-D17`). Last registered is asked first, so an app beats the kit it imported; a `readOnly` column is not offered to the registry — `sierra/src/junction/field-rules.js`
- `labelFieldInfo(fields, fallback, declared)` → `{field, source}` — **which column identifies a row to a person**, since a foreign key holds an id. Declared as `@@label(field)` in the seed, reaching the client as `x-label-field` and resolved once per resource onto `resource.labelField`; a picker asks the resource rather than scanning. **A declaration is not checked against the field rules**: its main case is a `@generated` full name, which is `readOnly` and absent from a create-mode registry, while the consumer reads it off a fetched row. Litestone refuses at parse every shape a picker cannot use, by name, because the options query SORTS by this column and searches it with `contains`. `source` is `declared` · `conventional` (one of eight names) · `scan` (the first plain string — a guess) · `fallback` (the id); the two guessing tiers warn once per field, naming the model and the fix, because a `Person` with `firstName`/`lastName` labels every option *Ada, Ada, Ada* and looks like it worked (`FJS-392`) — `sierra/src/junction/field-rules.js`
- `x-values` → `rule.values` → `controlFor` / `resource.options()` — **a declared value set, from the schema to the request a picker sends** (`FJS-D120`). `valueset <Name> { source · value · scope · where }` in `.lite`, `@values(<Name>[, required|open|suggested])` on the column, BESIDE `@relation`. **A bound column is asked before its foreign key**, because the set is the narrower answer — it names the scope and the column a person reads, where the relation names neither. Strength picks the control: `required` a picker, `open`/`suggested` both a combobox with `allowNew` (what separates those two is what the server does with a new value); a bound array is a multiselect where an unbound one is still `json`. **Every narrowing travels as a NAME** — `$checkWhere` validates a `$scope`, so it survives junction's `autoFilter`, and the offered list is the list the Data boundary will accept. A declared `where` is SQL, which a browser never sends, so it **mints a `@@scope` on the source named after the set** and crosses the same way; the predicate never leaves the server (`FJS-430`). Enforcement is litestone's, through the CALLER'S own accessor — `x-values` is an affordance, as `x-gate` is — `litestone/src/jsonschema.js`
- `resource.options(field)` → `{ options, total, truncated, error }` — **what a picker OFFERS, and why it has nothing to offer.** `error` separates *there are none* from *I could not ask* (`FJS-570`). It is said where the COUNT is said — `optionsNote` beside `truncationNote` in `@frontierjs/ui/utils.js`, composed through one `withNote`, so `Select`, `Combobox` and `MultiSelect` word it once — and it is a NOTE rather than a field error, because the value may be legitimately absent and marking the field invalid would refuse a submit on every optional relation whose rows did not arrive (`FJS-587`). `<Form>` keeps it beside `pickers` off the same prefetch and `defaultControlProps` carries it to a contributed control — `sierra/src/junction/resource.js` Ruled: `FJS-D456`.
- `toFieldErrors(err)` — same module, also `resource.fieldErrors(err)`. **The one owner of "a thrown value → per-field messages."** Three shapes reach it because each hop wraps once: `err.errors`, `err.data.data` (a server 400 through the browser client — the double `data` is real), `err.data`. Returns `{ fields, message }`. **`errors` is how a Data-realm refusal reaches a control**: junction's boundary adopts an error class's own `errors` array ahead of its `data`, so `ValidationError` and `UniqueConflictError` land under the box that caused them. An error whose payload is an OBJECT (`VersionConflictError`'s two revisions) is a form-level answer — `sierra/src/junction/field-rules.js`
- `$context.form` — the UI-side form seam, provided by `ui/components/forms/Form.mesa` as `{ errors, submitting, disabled, fields, submitted, optionsFor, reportInvalid }`. Nine controls resolve their own label, constraints, `aria-invalid` and message from it; an absent form reads `undefined` and every fallback is what the control does standing alone. A stated prop always wins, including `required={false}`. **`reportInvalid(name, message)` is the one channel going the other way** (`FJS-404`) — a control saying *the value I am showing is not one I can hand over*: a control whose element cannot hold every value the field may take writes only what it could convert, so the record keeps the last good value while the screen shows something else. It is the fourth error source and merges LAST, over a server message and a live one, because it alone describes what is on screen now. It refuses a submit even in a HAND-WRITTEN form, where the record-level checks stop (`FJS-316`), because the reporting control is on screen. `clearErrors()` leaves it alone; only its own control can retract it. `FJS-D225` uses it to mark a stored value the list no longer offers Ruled: `FJS-D457`.
- `buildRelations()` / `buildGate()` / `canAtLevel()` — same module. **`x-relations` is the only place a relation exists on the client**; `x-gate` is an affordance, never a boundary — `sierra/src/junction/field-rules.js`
- `x-version` — names the `@version` column an update must carry back, `readOnly` in the update schema and absent from the create schema. `createResource` remembers the version of every record it reads and puts it on the next patch. `resource.version(id)` / `.versionField` expose it — `litestone/src/jsonschema.js`
- `retryable` on a thrown error — the one thing a status cannot carry. A 409 is either a race (`VersionConflictError`, `TransitionConflictError` — re-read and re-apply) or a domain refusal (`TransitionViolationError`, `UniqueConflictError`, `SoftDeletedUniqueError` — show its message). Set it on any error class you own; `toFrameworkError` adopts it and it lands at `err.data.retryable`. `isStaleWrite(err)` reads it. **`junction errors` commits what a thrown value actually becomes** — `packages/junction/errors.snapshot.md`, every row executed through the boundary with Litestone's own classes, so a class gaining or losing a `status` shows as a diff (`FJS-255`) — `junction/src/core/errors.ts`
- `buildTransitions()` / `transitionsAt()` — `@@transitions` reaches the client as **`x-transitions` on the model, keyed by field**, never on the enum `$def`, because only a model can carry a per-transition `@gate`. **It is the GATE half of `db.<model>.transitions(row)` only** (`FJS-495`): the server grades the gate and the row policy — the `update` policy against the row as it IS and `post-update` against the row as it WOULD BE. A browser has no policy engine, so a move a policy refuses reads `allowed: true` there and 403s when pressed. **`refusedBy`** — `'gate'` · `'policy'` · `null` — lets a screen render *you are not senior enough* apart from *not this record*; neither a status nor a non-null `gate` separates them, since the gate is null for every ungated move a policy refuses. Permissive-when-unknown is the affordance contract; a screen needing the graded list asks the SERVER — `sierra/src/junction/field-rules.js`
- `buildCommitments()` / `commitmentsAt()` — `@@commitment` reaches the client as **`x-commitments`** (`FJS-D353`), keyed as declared (`abandon`, `subscription.lapse`), and comes back as the DATE a `@system` move falls due — the sibling of `transitionsAt` for the moves no button makes. **The date is `@frontierjs/toolbelt/datetime`'s `dueAt`, the function litestone's `due()` answers with**, so the two agree about when. *Is it still owed* is graded off the move's `field`/`from`, which each entry carries so a commitment across a relation needs no second document; the row that move is made on is the caller's to pass as `{ target }`, and one nobody read is not graded — `sierra/src/junction/field-rules.js`
- `modelNameFor()` / `schemaFor()` — `sierra/src/junction/schema-registry.js`, over `@frontierjs/toolbelt/inflect`. **The inflection rules are one module with five callers** — litestone's table name and its introspection, junction's `deriveModelName`, sierra's registry and `createResource` — because a table name and the model name derived back from it are the same rules run twice (Invariant 2). Regular English plus a fixed irregular table, so `people` resolves `Person` unaided; genuine ambiguity (`lens`/`len`) is said by hand — `createResource('lenses', { model: 'Lens' })`. A miss warns and degrades to a bare `make()`
- `authUserModel(db)` / `authMachineryModels(db)` — auth contributes INTO the schema, as two `.lite` files it ships (`auth/db/user.lite`, `auth/db/auth.lite`); `schema.ts` reads them and `authSchemaFragments(db)` is both, for a caller assembling one string in memory. **Split by owner** (`FJS-D16`): `User` is `@@gate("4.4.4.5")` with policies an app changes, so `fli auth:install` appends it into the app's own `schema.lite`; the `@@gate("8")` models go to `db/auth.lite` and are imported, so an upgrade reaches an installed app. The CLI reads the same bytes through auth's `exports` — it cannot import `schema.ts`, because `fli` runs on node and that file is TypeScript — `auth/schema.ts`
- `extend model X { … }` — **what an app says about a model it did not write**, so a package's models are imported rather than pasted. A package owns its columns; where those rows sit in the installing app — the relation back to its own `User`, `@@log(audit)`, `@@tenant(none)` under row tenancy — the shipped file cannot know. Adds only: an extend naming no model, a field the model already declares, and a second answer to a single-valued attribute (`@@gate` twice) are each refused by name; `@@allow`/`@@deny`/`@@index`/`@@unique`/`@@check`/`@@trait` are repeatable. Collected across the whole import tree and applied once it is merged, so a file may extend a model it is imported BY, and applied before traits. The opposite direction of `@@trait`, which the model opts INTO. A hand copy of a package's model diverges from it silently (`packages/litestone/docs/traits.md`) — `litestone/src/core/parser.js` Ruled: `FJS-D455`.
- `attachments` → `checkAttachments(config.attachments)` → the `check-attachments` start phase — **what this app needs and does not own, and whether this environment binds it** (`FJS-D158`). The app DECLARES in `junction.config.js`; the environment BINDS. The check reads `process.env`, not `fli deploy`'s recorded configuration set, which goes into the Release for identity and revert and is applied by nobody (`FJS-585`), so it holds however the variables arrived. `checkEnvField` is shared with `defineEnv`, so *present, non-empty, a URL, long enough* has one owner. An attachment adds three things a flat spec cannot say: these keys are ONE SERVICE, so a refusal names the service rather than a variable; ALL OR NOTHING, so `optional: true` forgives a service nobody bound and still refuses one **bound halfway**; and a DEFAULTED key is not evidence of binding. **The refusal is at startup**, and `fli`'s `showContainerTail` tails the container on a failed health check, on the revert path too, so the app's own sentence reaches the operator — `junction/src/core/attachments.ts`
