# Bridge index — detail

The full entry for each seam the `bridge-index` skill lists. Reached from the index; the index line is the one `seams.js` parses, so an owner changes THERE.

## UI

- `*.mount.js` in a routes directory — **a package's routes, mounted by one file** (`FJS-D282`), `sierra/src/scanner/walk.js`. It default-exports a directory (`export { default } from '@frontierjs/orion/routes'`) and its files appear under the mount's name, inside the app's own layouts. `walk` reports the VIRTUAL path, since URLs and layout chains are computed from it, and fills `sources` with the real one; `build-tree` STORES the real path relative to the root, so the route table, the prerender and the dev server resolve a mounted file with no change. The dev watcher follows every mounted directory
- `page.query` / `page.directives` — the URL's search string, split by `@frontierjs/toolbelt/directives` exactly as the bridge splits a request's. `resource.load(page.query, page.directives)` is a filtered, sorted, paged list that lives in its URL. `page.params` is path captures alone — `sierra/src/router/page-fields.js`
- `watchProxy()` / `createSignal()` / `createRoot(fn)` — the reactive seam and lifetime ownership — `mesa/src/runtime.js`
- `mount(label, Component, {props, root})` — page entry. Registers the delegation root; a component called directly renders but handles no events — `mesa/src/runtime.js`
- `renderComponent(src, opts)` — UI → HTML at build time; Sierra's `static` target composes route + layout chain through it. Children must be supplied **both** ways (`children={s}` and element children) — the two slot protocols do not bridge — `mesa/src/render-component.js`
- `appSrcDir(root)` / `appAliasPlugin()` → `renderComponent({ alias })` — **`@` is the SURFACE's own `src/`, and two resolvers must agree about it.** A surface is a Vite root, so `@/api.js` means a different file in `web/` than in `site/`; the base is that root and never `process.cwd()`. A prerender is the second resolver and knows nothing about Vite — it compiles a page and imports it under Node, where `@/api.js` is a package specifier — so `prerenderRoutes` passes the table it is already using. A wrong base surfaces only once an app writes its first `@/` import, as `Cannot find package '@'`. `@` is rooted at `src`, so a sibling of it (`config/`) stays relative — `sierra/src/build/app-alias-plugin.js`
- `swapInstances(entries, newFn, newSetMark, label)` — **the DOM a hot update replaces**, `mesa/mesa-vite/swap.js`. Two callers: mesa's own HMR client and jetty's `__jettyMesa.hot_update` (`FJS-259`). **No `import.meta` and no imports**, because jetty bundles it into an MV3 content script, which is a CLASSIC script. The client that wraps it is two files, so a plugin serving it at a virtual id must ask `client-source.js` for them joined — a virtual id resolves no relative import, and `client.js` alone is a 200 that dies in the browser — `mesa/mesa-vite/swap.js`
- `island(anchor, Comp, props, block, meta)` — the island seam, off by default. Markers are **comments, not an element** (an element is foster-parented out of `<tbody>` and joins `>` selectors). Sierra collects them at prerender, bundles one chunk per island, and mounts via `@frontierjs/sierra/islands`. **A mounted ancestor is authoritative** (`FJS-D89`) — test a marker with `isConnected`, not `parentNode` — `mesa/src/runtime.js`
- **The theme is a class on `<html>` and Sierra owns the switch** (`FJS-308`). `@frontierjs/css` owns the vocabulary — one `theme-*` class per theme, each a block of inheriting custom properties — and ships no JavaScript; beating first paint needs a `<head>` script only the build can write, so the kit cannot own the switch either. `theme: { themes, default, system, persist, key, apply }` in `sierra.config.js`; `setTheme` refuses a name the app did not declare. **The element is fixed at `<html>`** — `<body>` does not exist when a `<head>` script runs, so a body target would bring the flash back Ruled: `FJS-D453`.
- **There is no cross-package reactivity registry.** Sierra exports no module-level signal — `page`, `status`, `theme` are plain objects a component makes reactive with a `$:` path watch — so `sierra/src/build/mesa-plugin.js` passes mesa no `externalSignals` map, only `externalReactivityHints: 'strict'`. The map stays in mesa as an escape hatch for a third-party package that does export a signal. **Strict is the end state** (`FJS-D132`): the default tier is silent for a component that watches nothing
