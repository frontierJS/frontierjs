# `@immutable` and encryption

The full entries behind this section of the `data-hazards` skill's index.

- **`@immutable` is a column written once, and `asSystem()` cannot drop it either.** It refuses the KEY rather than comparing the value — the same number sent back is refused too — since nothing in the language sees the stored row beside the incoming one (`FJS-D162`). So it reaches the client as `readOnly` **in the update schema alone**: the one column kind whose answer differs by mode, since a create form must still offer the box. It is what a DOCUMENT is (`FJS-D162`) — an invoice's number, the instant it was issued, the total it was issued for — and the correction is a new row beside it. It says nothing about DELETE and nothing about the row: to freeze a row when it reaches a state, freeze its columns and let `@@transitions` own the state column. Refused at parse beside `@version` and `@updatedAt`, which the engine writes on every update.
- **A stored value names the KEY that wrote it** (`FJS-D183`). The envelope is `v2.<kid>.<payload>`, the kid a domain-separated HMAC of the key truncated to eight hex characters — it identifies a key without being one, so it is safe in a column, a log line and an error. `$rotateKey` runs **one transaction per DATABASE**, so a crash between two commits leaves each database saying which key wrote it and the rotation resumable. **An unknown kid still tries the ring**: GCM's tag is the authority and the kid is only the ORDER. `createClient({ previousEncryptionKeys })` is read-only, the old key STAYS on the ring after a rotation, and re-running one finishes it. **A half-rotated schema is not supported**: a deterministic encoding is a function of the key, the operand is widened across the whole ring at all four spellings of equality, and every equality filter over a not-yet-rotated row would answer nothing. **A caller may not send a ciphertext-shaped value** (`FJS-715`), and the same check gates the HASH path. **A decrypt that fails is RAISED** (`FJS-716`), naming the kid wanted and the kids held; the one column that still degrades is `@secret(rotate: false)`, whose loss the app declared, so raising would make the whole row unreadable for one column.
