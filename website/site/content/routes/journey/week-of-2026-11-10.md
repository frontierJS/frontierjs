## The week in numbers

- **243** Claude Code sessions in the framework repo, between 16 and 53 a day.
- **258** issues filed and **165** closed.
- **216** design questions ruled and written down, each with the options it beat.
- **7** new stressor apps started: a music player, a writing assistant, an escape-room game, a code editor, a color tool, a git forge and a board-game mechanic generator.
- **$11.69** for one unattended fix-loop batch that closed 20 of 23 issues, and **$11.17** for an eight-case deploy matrix that ran in an hour and a half.

A stressor app is a real app we build only to find where the framework is thin. Each one files issues against FrontierJS as it goes, so the number of issues filed goes up as the apps get more ambitious, and that is the point.

## What broke

**A fix loop that closed issues it never fixed.** The fix loop runs agents side by side overnight, each in its own copy of the repo, and merges their work back in the morning. When a merge conflicted, the issue stayed marked closed, though none of its code had reached the main tree, and the next run to reuse that copy wiped the work. Now a conflict reopens the issue and attaches the conflicting files and the patch, so nothing is lost and nothing claims to be done when it isn't.

**A baseline that failed its own test.** Mesa's bundle-size gate started failing by five bytes, and no commit had caused it. The baseline numbers had been measured from a working tree with uncommitted changes, so the commit that recorded them failed its own gate. We adopted the committed tree's numbers. A baseline is only as good as the tree it was measured on.

**A list with nowhere to put its rows.** A virtual list placed at the top level of a component had no element to attach to, so it tried to add its rows to an invisible placeholder and threw. The compiler now refuses that shape and names the missing scroll container. Our own guide's example had the broken shape too. The test that runs every code sample in the docs is what caught it.

And an honest one about the fix loop: of the 20 issues it closed, about half didn't reproduce on a quiet machine. They were flaky because other work was running at the same time, not because the code was wrong.

## A call we made

The framework's own HTTP headers had drifted into two spellings, `X-Fjs-*` and `X-Frontier-*`. We picked one, `X-Frontier-*`, and moved every header in a single change across about 59 files, with no alias kept for the old names. A developer who already knows `FRONTIER_API_URL` can guess `X-Frontier-Key`, but nobody could guess which headers were `Fjs`. Nothing has shipped yet, so there was no one to stay compatible with but ourselves.
