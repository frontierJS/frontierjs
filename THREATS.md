# Threats — who attacks a FrontierJS app, and what each boundary promises

One row per adversary and boundary. Each row names the ruling or invariant that holds the boundary, the file that enforces it, the test that proves it, and any hole open today. The reasoning lives in the ruling. This page says where to find it and does not restate it (`FJS-D656`).

`fli check`'s `threat-row` fails a row whose *Proved by* names no test, or names a path that is not in the tree. A path is written from the repo root. A test that asserts an open hole (`test.failing`) belongs in *Open*, not in *Proved by*, and `threat-row` holds the converse: an *Open* cell whose every `FJS-###` is closed, or that names a test with no `test.failing`, is an error.

*ASVS* names the OWASP ASVS 5.0 requirements the promise answers to (`FJS-D1194`: Level 2 throughout, Level 3 for authentication and tenant isolation), and `threat-row` fails a row naming no requirement (`V8.2.1`; a bare chapter is not one). Every requirement in that scope is graded in `docs/ASVS.md`, with the `FJS-###` of each gap. B8–B10 cite Level 3 requirements (`V4.1.5`, `V12.3.5`) because the signature they promise is one.

## Words

**Adversary** and **Promise** are defined in `VOCABULARY.md`. **Boundary** is always qualified (`FJS-D06`). **Origin** is left open (`FJS-D656`): the browser's sense and PHILOSOPHY's *one origin* of truth are both live, so a row says *app origin* or *static origin* and never the bare word.
