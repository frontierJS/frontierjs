# Workbench -- layout

The file-by-file map. `CLAUDE.md` keeps the owners and the traps. Paths under
`api/src/` and `web/src/` match Basecamp's, because the wing moves in unchanged.

| Path | What |
| --- | --- |
| `db/schema.lite` | Member · Session (Haven's door) · ClaudeTranscript · ClaudeMessage · ClaudeWrite; no tenancy, no audit database |
| `db/migrations/main/` | generated by `bun run db:migrate`; nothing has shipped, so no upgrade step |
| `db/schema.d.ts` | generated by `bun run db:types` |
| `api/index.ts` | starts the app on `PORT`, else 5501 (`GLOBAL.workbench`) |
| `api/src/app.ts` | builds the app, never starts it; claims `app.own('workbench', ...)` |
| `api/src/workbench.types.ts` | types the claim by augmenting junction's exported `App` interface |
| `api/src/core/env.ts` | the environment: `WORKBENCH_KEY`, `ENCRYPTION_KEY`, `WORKBENCH_DIR`, `CLAUDE_BIN`, `HOST`, `BASECAMP` (the name of an entry in `basecamps.json`). No `LOCAL_MACHINE` -- this app IS the local machine |
| `api/src/core/workbench.ts` | `createWorkbench` -- the pins' directory and the Claude binary |
| `api/src/auth.ts` · `login.ts` · `principal.ts` | the door: mint a Session, read a token back to its member, `/door/*` routes, the per-call principal |
| `api/src/peer.ts` | this machine's peer key pair, minted into `~/.config/workbench/peer.json`, and `GET /door/peer` that shows its public half |
| `api/src/domain/peer/` | `peer-call.ts` gives conduit's peer dialer Workbench's status for a refusal; `basecamp.ts` is `app.basecamp`, the dialer for Basecamp's `apps.preview` |
| `api/src/{domain,services,jobs,plugins}/` | the wing: atlas, claude, workbench and local domains; their services, jobs and the terminal plugin. Every reader of Claude Code's files (transcripts, sessions, the configuration scan, quota, context) and its `auth`/`mcp`/`doctor` subcommands are `@frontierjs/claude`'s; `domain/claude/` keeps the usage index, spend, prices and the writer, and `domain/local/local-claude.ts` the binary and env they run with |
| `api/src/domain/laptop/` | fli's files on this machine, read through `@frontierjs/cli/core/{home,services}.js`: `laptop.ts` (Disk, Clear, Remove lane), `keys.ts` (secret files and their modes, the Frontier identity), `settings.ts` (global env masked, user commands), `running.ts` (dev servers and tree holds), `services.ts` (every service fli signs in to, its probe on request, the commands that use it), `builds.ts` (Rust `target/` folders under `CODE_DIR`, default `~/code`, with size and age, and Clear for one), `docker.ts` (Docker's images by repository, build cache and volumes in `docker system df`'s figures, and Clear for unused images and the cache), `vitals.ts` (the machine itself -- free disk per drive, memory, load, heat, battery, a pending reboot -- read by Home). The `laptop` service is model-less and gated at ADMINISTRATOR, like `basecamps` |
| `web/src/routes/laptop/` | `/laptop/`: tabs Disk, Keys, Running, Services; `web/src/resources/Laptop.mesa` is its resource |
| `api/src/domain/capture/config.ts` · `connect.ts` · `web/src/routes/capture/` | Capture's `~/.config/capture/config.toml` (the Rust tool's `Config`): read as Rust loads it, written only when Rust would accept it, at 0600, unknown keys kept, the share key never returned. `connect.ts` is the key hand-back (Connect, the `/capture-connected` landing the share app's browser returns to, and Test): one pending attempt in memory, the key written through `setCaptureConfig`. `/capture/` is the screen; `web/src/resources/Capture.mesa` its resource. Tests pass `{ file }`, never the real path |
| `api/src/domain/capture/files.ts` · `services/capture/capture.service.ts` (`files`, `open`, `reveal`, `share`, `removeFile`) · `web/src/routes/captures/` · `components/capture/CaptureCard.mesa` · `lib/capture-files.js` | The Captures gallery: the media in Capture's `save_dir`, newest first, kind by extension, a `.txt`/`.vtt` paired with its recording or call. A file is named by its basename and resolved (realpath) to a direct child of the folder; Open, Show in folder and Share spawn `xdg-open`, `gdbus` (FileManager1) and `capture share` on the API's machine. Bytes for a tag are the raw `GET /capture-file/{name}` (Range answered), which a page reads through `client.fetch` into a blob URL, as the chat's files do. `api/test/capture-files.test.ts` runs over a temp folder and never spawns |
| `api/src/domain/servers/servers.ts` | The Servers screen (`FJS-D2006`–`FJS-D2008`): each `ProviderAccount`'s machines listed live through `@frontierjs/conduit-hetzner` / `conduit-digitalocean` (only `list` and `verify`, never create or destroy), one failing account erroring alone; `add` verifies the token before storing it. `services/servers/servers.service.ts` is its model-less service |
| `api/src/domain/local/local-ssh.ts` | `~/.ssh/config` Host aliases, resolved offline by `ssh -G`: the hosts shown beside the cloud machines. A copy of Basecamp's, not an import |
| `web/src/routes/servers/` | `/servers/`: machines grouped by account, the ssh hosts, fetched-at and Refresh, Add account and Remove; `web/src/resources/Server.mesa` is its resource |
| `api/src/domain/prototypes/catalog.ts` · `web/src/routes/prototypes/` | `/prototypes/` (`IDEAS/prototypes-catalog.md`): every fjs-prototypes repo, its record from `catalog/CATALOG.json` (`PROTOTYPES_DIR`) merged with the git scan, grouped by owner, kind or status; favorites, hand order and folded groups in `WORKBENCH_DIR/prototypes.json`. `domain/prototypes/candidates.ts` is the Merge candidates panel: pairs linked by `related`, and same-kind pairs whose `db/schema.lite` share two model names that fewer than a quarter of the schemas declare. `domain/prototypes/move.ts` is Move: the folder, its record's `path`, and every `~/.claude/projects/` folder its sessions started in, each transcript's `cwd` rewritten (`FJS-D2279`), and every relative symlink out of the repo re-pointed; refused while pinned or while a process runs inside. `web/src/resources/Prototype.mesa` is its resource |
| `api/src/domain/local/lathe.ts` | Open a folder in Lathe: the workbench's Open on a pin and the prototypes page's Open on a record |
| `api/src/domain/basecamps/` | The Basecamps in `basecamps.json`: `basecamps.ts` (list, Back up now, Restart), `basecamps-create.ts` (`basecamp:create` as a logged child; `spawnFli` is the shared spawn) and `basecamps-reinstall.ts` (`basecamp:reinstall` on an entry's box under its admin `apiKey`, never its run `scopedKey`, `FJS-D2031`) |
| `web/src/routes/charter/` | `/charter/`: the `runs: true` entry with which keys are filed, *New box* to `/basecamps/new/`, and *Reinstall* (restore or fresh, Plan only by default) with its log tailed (`IDEAS/charter-to-live.md` Phase 2) |
| `web/src/routes/charter/drill/` | `/charter/drill/`: the restore drill. *Rehearse* reads the box and plans; *Run for real* backs the Basecamp up, reinstalls it, then grades the hub's rows, the Apps' serving and one kept App's data. `api/src/domain/charter/restore-drill.ts` grades, `restore-drill-run.ts` is the detached process, records in `~/.config/workbench/drills/` |
| `web/src/routes/terminal/` | `/terminal/`: one shell in the home folder, outside any pin; ui's `Terminal.mesa` with an empty `session` (`web/src/lib/terminal.js`), over `WS /ws/terminal` (`api/src/plugins/workbench-terminal.ts`), its tmux session the bare `workbench` |
| `web/src/routes/recommended-services/` · `web/src/lib/recommended-services.js` | `/recommended-services/`: one service per job that we run on and recommend, with alternatives; the rows are the static table in `lib/recommended-services.js`, edited there |

| `web/src/routes/terminal/` | `/terminal/`: one shell in the home folder, outside any pin; ui's `Terminal.mesa` with an empty `session` (`web/src/lib/terminal.js`), over `WS /ws/terminal` (`api/src/plugins/workbench-terminal.ts`), its tmux session the bare `workbench` |
| `api/config/junction.config.js` | port and CORS origins |
| `web/config/` | `sierra.config.js`, `vite.config.js` (5508, `strictPort`), `api-paths.js` (derived from `app.snapshot.md`) |
| `web/src/App.mesa` | the sign-in guard |
| `web/src/routes/_module.mesa` | the shell: topbar, nav, sign out |
| `web/src/routes/{index,login,workbench}/` | root redirect, the sign-in page, the empty state |
| `web/src/routes/home/` | `/home/`, where `/`, sign-in and the brand link land (it has no nav entry): needs-you, working chats, pins (idle ones as chips), recent sessions, dev servers, Autopilot, unread. Reads other screens' services and writes nothing; what it read is held in a module-level cache for the tab's life, so a return draws at once and re-reads only past a minute. A row links `/workbench/#workbench-<pin>/<chat>`, which stages the pin and opens the chat |
| `web/src/lib/{nav,session}.js` | the nav table; who is signed in |
| `desktop/` | the Tauri shell around `web/` (`wraps: 'web'`, `api` 5501): `config/desktop.config.js`, `deploy/build.mjs`, `shell/` (crate `workbench-desktop`, window `Workbench`, icon from `brand/assets/icons/`; one instance, `--go <path>` from a second launch in `src/go.rs`), `test/verify.mjs` + `probe.js` (sign in at the door, scan a fake `~/code`) |
| `config/api-origin.js` | turns `FRONTIER_PORT_BE` into the build's `FRONTIER_PUBLIC_API_URL`, read by `desktop.config.js` |
| `app.snapshot.md` | `junction app --app api/src/app.ts`; read by `web/config/api-paths.js` |
