# Junction — Project Context

`@frontierjs/junction` is the API realm: services, the hook pipeline, HTTP and
WebSocket transport, channels, the browser client, and the batteries. TypeScript,
Bun-only. It sits above Litestone and below Sierra, and never imports Sierra
(Invariant 1). Litestone is an optional peer reached by dynamic `import()`, so
junction runs without it and a static import of it under `src/` breaks every
modelless app at load.

## Rules a change must keep

Each names its pin; the full wording and every test file is `docs/hazards.md`
§ Rules, the failure behind each `docs/internals.md`, by path.

- **A broadcast is graded per recipient**, with the DECLARED `model:` as accessor (`FJS-D175`, `FJS-672`, `FJS-700`); claims are the app's to state, per channel (`FJS-749`); a room is regraded after every committed write its read policy reaches (`FJS-D596`).
- **`channel:` or `announce()`, never both** (`FJS-045`). **A write is done when the OUTERMOST transaction commits** — `afterCommit` and the announcement drop on rollback (`FJS-682`, `FJS-688`).
- **The gate wraps every hook an app wrote** — `around(gateAuth) → before → validated → method → after` (`FJS-403`).
- **A scoped key reaches only a method declaring that `scope:`**; one naming none refuses it (`FJS-D916`).
- **A custom method takes the model's read gate as a floor** (`FJS-826`, `FJS-D408`); **an omitted `model:` resolves from the service NAME**, `serviceAccessor()` is the one reader, never `model ?? name` (`FJS-D628`).
- **Bulk PATCH/REMOVE writes one row at a time through `update()`** (`FJS-044`). **An `Idempotency-Key` needs a principal and names ONE request** (`FJS-680`).
- **The METHOD decides list vs single; a stream is refused by name** (`FJS-140`, `FJS-D13`, `FJS-1693`). **A thrown value's status is committed** in `errors.snapshot.md` (`FJS-255`).
- **Every socket bound is the socket's own** (`FJS-705`, `FJS-704`); presence is opt-in, batched (`FJS-703`); a reconnect is a gap (`FJS-701`); an unverified WS token closes 4001 (`FJS-702`); an unfinished shutdown exits 1 (`FJS-693`).
- **A config key reaches the app only where `loadConfig` maps it** (`FJS-1066`, `FJS-D256`). **A route registers once** (`FJS-225`).
- **A webhook destination is graded at registration and before every attempt** (`FJS-681`, `FJS-D193`); a subscription dedupes on the SIGNED body id, and dedupe means applied (`FJS-D1087`).
- **A CRLF in a mail address is refused at the builder AND `sendMessage()`** (`FJS-677`); a reply tag proves only receipt (`FJS-D1091`, `FJS-D1092`); mail arrives through a conduit Receiver, never a route.
- **The static server serves inside its root**, symlinks resolved (`FJS-746`); vectors shared with sierra (`FJS-D653`).
- **`$` throws outside a call, and an ended call is outside it** (`FJS-687`).
- **A guest's claims never become `ctx.user`** (`FJS-D113`); **`principal` may be a list**, a name two emit refused (`FJS-D522`, `FJS-D694`); a grant is minted through `bearerClaim`'s `mint`/`redeem` (`FJS-D819`), a session beside one is 400 unless `session: 'merge'` (`FJS-D832`).
- **A claimed mirror's write lands at the Provider first** (`FJS-D1125`); `mirrorClaimFor` is the one reader.
- **A test names no port** (`FJS-900`). **The package typechecks to zero, `test/` included** (`FJS-034`, Invariant 14).

## Proving a change

```bash
bun run test            # test:all adds the example
bun run typecheck       # must be clean
```

A change to the devtools plugin or `core/call-as.ts` also needs the cli's
`bun run test:browser:console`: devtools serves no page, and `fli gui`'s
`:live`, `:call`, `:data` and `:ask` are what read it, in both targets.

Then `example` `bun run verify` and `verify:jobs`, and `basecamp` `bun run verify`.
A change to channels or `announce` also needs `example` `verify:live`, the only
drive that watches a SECOND tab and so tells a broadcast from a tab's own echo.
A change to either transport's context also needs `@frontierjs/testing`'s
`bun run test`, whose parity runner puts one call down both.

**`bench/cases.mjs` is the timed tier and is not in `test`.** Four requests
through `app.http.fetch`, each beside a hand-written fetch handler running the
same statement, and each must answer 2xx — a refused request is faster than a
served one. CI's `perf` phase runs it against the base ref (`node
scripts/bench-ab.mjs --only junction` from the root) and never fails on a time;
a case that throws fails it.

| A change that adds… | …joins |
| --- | --- |
| a `junction.config.js` key | a behavioral row in `test/config-surface.test.ts`, naming its axis |
| a `ServiceContext` field | `test/context-contract.test.ts`, which runs each field's rule and names its axis |
| a `src/` directory, or a core import of a battery | `test/edge.test.ts` — classified, or an allow-list row that is a ruling |
| an error class or a status | `errors.snapshot.md`, regenerated by `junction errors` |
| a broadcast path | `test/realtime-grading.test.ts` — one recipient admitted and one refused |
| a cache behavior | `test/cache-conformance.test.ts` — one body, both drivers |
| a documented OpenAPI operation | `test/openapi-round-trip.test.ts`, which calls it |
| a cross-package behavior | `test/real-litestone-client.test.ts`, against a real client |
| a type on the far side of the wire | `test/client-types.test.ts`, which compiles a fixture with `tsc` |

## Where things are

`docs/layout.md` is the file-by-file map and the where-to-look table; read it
when a change touches a file this list does not name. The owners that matter
on most turns:

- `index.ts` is the four axes and the host, no battery · `src/core/app.ts` is `createApp` and the plugin protocol · `src/core/service.ts` is `createService` and `callService`.
- `src/core/context.ts` is `ServiceContext`, the request store (`enterRequest`, `reenterAs`) and the call store (`$`, `enterCall`).
- `src/core/hooks.ts` · `hooks-builtin.ts` · `hooks-resilience.ts` are the pipeline; `src/core/litestone.ts` is the Data adapter; `src/core/envelope.ts` the result envelope; `src/core/errors.ts` the named HTTP errors.
- `src/transport/bridge.ts` is the transport↔service handoff · `http.ts` is `Bun.serve` · `channels.ts` + `presence.ts` + `send-queue.ts` are realtime · `src/config/index.ts` is `loadConfig`.
- `src/client/index.ts` is the browser client · `src/plugins/` the batteries (`declared.ts` is the one plugins module core names) · `src/mail/` the mail kit.
- `tools/cli.ts` is the package bin; the snapshots, `atlas.ts`, `call.ts` and `repl.ts` sit beside it · `db/` ships `.lite` fragments · `test/` is one file per concern.

## What bites here

The traps that bite most; the full catalog is `docs/hazards.md`, read it before
touching a hook, a transport context, a battery or `boot()`.

- **Path captures are `ctx.route`**, no `ctx.params` on either context (`FJS-D03`); a raw route writes `{id}`, `:id` is literal.
- **`app.get`/`app.post` apply `apiPrefix`**; `app.http.router` is the escape.
- **`update` is `patch` with an id required, and it MERGES** (`FJS-D179`).
- **`after` is after the METHOD** — `ctx.afterCommit(fn)` must not run early, `ctx.enqueue(job, payload)` must not be lost.
- **`register` is sync**; async setup goes in `boot()`; only a throw in `ready` lets the app start.
- **A timer in `boot()` ticks in every one-shot process** — `_startOnce()` skips `work()`; a worker or `setInterval` goes in `work()` (`FJS-D551`).
- **Internal directives ride `{ directives }`**, filters first argument; **`_find`/`_get`/`_create` skip junction's hooks, keep Litestone's gate.**
- **A frame goes out through `wsSend()`** (`transport/send-queue.ts`), which holds what Bun drops.
- **`ctx.data` is a row or an ARRAY**; a `__`-prefixed context field is a declared contract — a cast to `Record<string, unknown>` is the smell.
- **Probe a Litestone client with `'x' in db`**, `typeof db.x` throws; `$tapQuery`/`$tapEvents`/`$logContext` are ROOT-only (`FJS-673`).
- **The edge is four axes and a host** (`FJS-D639`); a battery sits behind a subpath, allow-listed in `test/edge.test.ts`, typing `app.<slot>` by augmenting an empty `App*` interface (`FJS-D640`, `FJS-D643`); `createApp({ db })` is the one way in (`FJS-D641`).
- **Junction owns no file store** (`FJS-D260`), only the crossing: `transport/body.ts`, `transport/bridge.ts`, the client's `File`.
- **A standing is the app's mapping** — `callerGateLevel` asks `db.$levelOf`; `sessionGateLevel` never reads `role` (`FJS-D308`). **`createApp({ tenants })` replaces `{ db }`.**
- **Helmet is on until `http: { helmet: false }`; CORS, DDoS gate and rate limiter are off until configured**, `'*'` never applied for you.
- **A test injects a transport, never `mock.module()`** — process-wide in bun (`FJS-908`); a hand-built context sets `ctx.result = null`.
- **An `around` ending the call without `ctx.result` is a 500, not 204** (`FJS-946`), graded only on a `hookContext`-built context.

## The two contexts

Which one you hold is decided by where the code is mounted.

| | `TransportContext` | `ServiceContext` |
| --- | --- | --- |
| You get one by | `app.get` / `app.post` / a middleware / a WS handler | a service method, any hook, `app.service(x).method()` |
| Created per | **request** | **call** — one request may make several |
| The principal | `ctx.user` — flat, may be `null` | `ctx.user` — frozen, propagates |
| Caller environment | `ctx.ip`, `ctx.headers` | `ctx.caller.{ip,userAgent,headers}` |
| Path captures | `ctx.route` | `ctx.route` — `{}` on an internal call |
| The URL's search | `ctx.query` — **raw, `$` keys present** | `ctx.query` (filters) + `ctx.directives` (shape) |
| Scratch | — | `ctx.locals`, fresh every call |
| Wire-only keys | — | `ctx.transients` (payload), `ctx.reserved` (query) |
| Columns the app supplies | — | `ctx.system`, a Set a hook adds to |
| Responding | `ctx.json` / `text` / `html` / `file` / `sse` / `paginate` | return a value; the envelope is built for you |
| The scoped client | — | `$.db` — its one spelling; never on `ctx` |
| Reaching the other | — | `ctx.raw` — the transport ctx, or `null` |

The bridge copies `route` and the principal across unchanged. The HTTP and WS
paths build a context separately — `bridge.toContext()` and `bridge.internal()` —
so a fact one derives, the other must lift out of the frame by hand.

**Two stores.** The request store holds `RequestMeta` and its one owner is
`enterRequest(src, fn)` / `reenterAs(user, fn)`. The call store is `$`, the
`ServiceContext` of the call in progress, opened around the whole of
`_callService`; `enterCall(ctx, fn)` opens it for a hand-built context.

## Seams this package owns

- **`transport/bridge.ts`** is the transport↔service handoff: nothing above it
  touches `req`/`res`, nothing below touches a service.
- **`callService`** is the one announcement point, for the bus and the channels.
- **`core/litestone.ts`** is the Data adapter — `withLitestoneDb`/`withTenantDb`,
  `gateAuth`, `autoValidate`/`validateInput`, `toDataPrincipal`.
- **`core/directives.ts`, `core/events.ts` and `core/methods.ts` import nothing**,
  so the browser client names them without pulling `node:async_hooks` into a
  bundle (`FJS-1181`). `methods.ts` is `CRUD_METHODS`, which `envelope.ts` reads
  to decide list against single (`FJS-D937`).
- **`core/call-as.ts` is the one call made from outside the app** — `junction
  call` in a booted copy, devtools' `POST /api/call` inside a running one,
  refused outside development (`FJS-D1426`). `rowsAs` beside it is devtools'
  `GET /api/data/<Model>`, a page of rows through `app.withDb` under the same
  principal lookup (`FJS-D1427`). `actAs` is devtools' `/api/mcp`: one MCP
  request handed to `app.mcp.answer` as the principal `?as=` names, refused
  outside development (`FJS-D1428`).
- **`core/app-model.ts` is one walk over a built app**; the snapshot tools under
  `tools/` render it and hold no walk of their own.
