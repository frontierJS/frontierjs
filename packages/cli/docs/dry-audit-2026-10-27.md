## Headline

Block-level cloning in core/ is LOW (23 duplicated 6-line windows across 168 files). The
repetition is (a) micro-helpers redefined per file, (b) parameterized templates written out
by hand per surface, (c) commands re-doing what a prelude or core module already offers,
(d) seven HTML pages each carrying their own chrome. Each family carries DRIFT = latent bugs.

Already dry, leave alone: core/checks/*.js rules (go through checks/lib.js: sources/scripts/
readCode/lineOf 40+ sites; 5 hand walk-loops in ui.js only), console/ screens, tutor steps
(narrate/needs/restartApi in tutor/_module.md <script>).

## Mechanism fact that reframes the commands layer

`commands/<ns>/_module.md` is NOT prose-only. A `<script>…</script>` block there is the
namespace PRELUDE: core/registry.js:126 (scriptBlockOf) extracts it and core/runtime.js:717
compiles it into every command body AND every `_steps-*` step of the namespace.
deploy/_module.md holds 35 helpers this way (deployConfFor :251, resolveTarget :229,
resolveDeployConf :304, resolveSide :331, machineFor :95, swapContainer :662 …).
CLAUDE.md:40 "a fenced block in a _module.md renders as an empty heading" is true of a ```js
fence and misleads about <script>. Fix the line. Constraint: module scope — no log/echo/flag/$;
a helper takes $ as a parameter.
