# conduit-37signals — package map

`src/index.ts` `basecampTargets()` (`api`, `person`, `token`, `stream`), `bindBasecamp` (`as: 'api' | 'person'` chooses whose credential `api` spends), `basecampTokenResolver`, the reads (`walk`, `me`, `projects`, `project`, `recording`, `todolists`), the feed (`pollEvents`, `FEED_TYPES`, `eventJobId`, `reread`), the stream (`basecampStreamDialect`), the verbs (`createTodo`, `completeTodo`, `postMessage`, `comment`, `chatLine`), `findCreated` · `src/errors.ts` `translate` · `src/types.ts` Basecamp's shapes · `sink.ts` · `test/37signals.drive.ts` · `test/fixture/` scrubbed bodies and headers from Kobami's account (its README lists each request). The plan is `frontierjs/IDEAS/conduit-37signals.md`; the next step is its first open box.

## What bites

- **The account is the address**, `https://3.basecampapi.com/<accountId>`; a call's `path` starts after it (`/my/profile.json`). A path that repeats the account reaches `/999/999/...`, a 404.
- **The `User-Agent` is the builder's to refuse.** Bun fills an absent header with `Bun/<version>`, which Basecamp answers 200; only an empty one gets its `400`. So a target that dropped it runs, unnamed.
- **A 404 is `gone` to this principal** — deleted and never-visible answer alike (the sink's `hide` is the second). A TRASHED recording is unmeasured: `recordings.md` lists `status=trashed` as a filter, so it may read `200`. Only `Reason: Account Inactive` makes it `inactive`. A mirror never reads `gone` as a deletion.
- **A 403 is `forbidden`, not a bad key.** Conduit grades it `auth_failed`; reminting changes nothing. `translate` reads the status.
- **`walk()` stops on an empty page, not on a missing `Link`.** `projects.json` names a next page past its last, forever. A `Link` URL is followed whole, as the request's `address`, never joined to the account.
- **The envelope is not the recording.** `buckets/{b}/recordings/{id}.json` answers the fields every recording shares and nothing a mirror applies (`completed`, `content`, `description`); its `url` is the typed read. A re-read that has the type takes the typed path.
- **One `ETag` per page.** A page's tag says nothing about the next page, so a list is `unchanged` only when every page answers `304`.
- **A create is never resent, and `findCreated` is its only way back.** No key exists, so `replayable` stays off every create; turning it on posts a lost comment twice. The read is the parent's list (the path the create posted to), not the feed, which serves nothing younger than about 30 s and promises no delivery. `completeTodo` alone is replayable: a completion is a state. A 500 on a create is `indeterminate` (it may have landed) and a 429 is not (refused, so send again after `retryAfterMs`); `findCreated` tells a 500's two outcomes apart.
- **Rich text is `{ text }` or `{ html }`, and a chat line is rich text too.** `{ text }` is escaped here; a line always sends `content_type: text/html`, without which Basecamp stores a plain line whose form no read has measured. `findCreated` strips tags BEFORE decoding entities (an escaped `&lt;x&gt;` is the writer's text) and compares a plain field, a to-do's name or a subject, as written.
- **A message without `status: active` is a draft**, which nobody sees; `postMessage` always sends it.
- **The token resolver is the mint, never the cache.** `withCache({ ttl_ms: Infinity })` around it is what makes one refresh for two sends and holds the token to `expires_in`; a hand-built in-flight map beside it is what `FJS-D1075` removed. The refresh is unreplayable, as `conduit-oidc`'s is: a resent refresh after a rotation is `invalid_grant` on a live grant, which `onLost` would then mark dead.
- **`person` spends the caller's grant, and only `grantsFor(who)` knows whose that is.** One resolver serves both refs; `getFor` exists only when `grantsFor` was given, so conduit refuses a `person` target against an app-only resolver. What nothing can see is a `grantsFor` that ignores `who` and answers one row for everyone: that sends one person's token as every caller, the hole conduit's `CLAUDE.md` names for a `getFor` that ignores `grant`. `onLost` and `onRotated` land on the caller's own store, so one person's `invalid_grant` ends their grant alone.
- **A poll is one page, never a walk.** The caller stores `position` after each event on its page is queued under its own id, `dispatch({ id: eventJobId(event) })` (`FJS-D1354`), so a replayed page queues nothing new and dedupe by event id is caravan's primary key, not a ledger here; a walk inside the connector would answer a position for pages nobody applied. `next` and a 410's `resume` are followed whole with `{ url }` and carry their own filters, so nothing is added to them. Re-entry is the caller's, by the failure's `code`: `invalid_position` and `filters_changed` by `since`, `before_epoch` by `resume`. `translate` names a 409 or 410 by status alone, which holds because only the feed answers either (read from bc-api). Never `exclude_performers=self`: under Jordan's token it drops Jordan.
- **The apply job applies `reread`'s answer, never the event.** An event is minutes old by the time its job runs, so the row applied is the recording now, and an echo of the app's own write lands the state it already holds. `gone` is a drop, returned rather than thrown, because a retry asks the same 404 again. A boost's `recording_id` is the BOOSTED recording, read through its envelope.
- **A stream frame is dispatched as its event's job, never used to wake the poll.** The poll serves an event only once it is about 30 s old, so a woken poll finds nothing; `eventJobId` is the frame's receipt key and the job id, so the poll's later dispatch of the same event is caravan's no-op. Only the poll stores `position`.
- **The stream URL is minted per dial and never built.** `dial` posts `stream_ticket.json` through `api` and answers its `url` whole; a ticket lives two minutes, so a cached URL redials into a `401` forever. The target is `auth: none` because the ticket is the credential (`FJS-D1355`), and conduit refuses a dialing framing on a target with one.
- **ActionCable takes no client ping.** An unknown command is `disconnect` with `reconnect: false`, so the keepalive is listen-only, `beat` on the server's 3 s `ping` and `dead_ms` 9 s (`FJS-D1356`). A `reject_subscription` is thrown from the handshake and redialed, a ticket per backoff step.
- **A fixture is client data, scrubbed.** `fixtures.scrubbed` fails on any address that is not `person-N@example.com` or an account that is not `999`; a new capture is scrubbed before it lands here, raw dumps stay in a scratchpad.
