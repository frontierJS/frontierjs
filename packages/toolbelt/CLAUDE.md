# toolbelt — package map

**`@frontierjs/toolbelt`** — pure functions, zero dependencies, importable from
anywhere in the tree including litestone and mesa. One rule: **every export is a
pure function** — same input, same output, no I/O, no clock, no globals, no
framework import, no mutation of its arguments. The rule is the package's
license, not its style: `FJS-D26` admits toolbelt as substrate *below* the
dependency graph on the strength of it, so breaking purity costs the standing.

**One kit per subpath.** `/aria`, `/bearer`, `/cells`, `/cron`, `/datetime`, `/devline`, `/docfences`, `/env`, `/frontier`, `/frontmatter`, `/gate`, `/geo`, `/glow`,
`/fill`, `/ids`, `/inflect`, `/directives`, `/history`, `/hooks`, `/json`, `/jsonschema`, `/keys`, `/mailbox`, `/markdown`, `/match`, `/mime`,
`/predicate`, `/query`, `/rank`, `/redact`, `/seal`, `/search`, `/signature`, `/sigv4`, `/sse`, `/sugar`, `/textbox`, `/textedit`, `/trace`, `/transforms`, `/tty` and `/units` today; a caller
importing one gets nothing else. There is no root `.` entry.

`bun run test` — `test/run.js` is the whole harness, no dependencies, runs
under node too.

## Where things are

`docs/layout.md` is the file-by-file map, one entry per kit; read it when a
change touches a kit this list does not name. The owners that matter on most
turns:

- `src/<kit>/<kit>.js` is each kit, `src/<kit>/<kit>.d.ts` beside it where a TypeScript caller reads it; `package.json` `exports` is the subpath table — a kit not listed there is not importable.
- `src/inflect/` and `src/directives/` are load-bearing: Invariant 2 (one spelling across litestone, junction, sierra) and Invariant 10 (the `$`-key table the bridge strips by).
- `src/gate/` is the one binding of `@@gate` levels, `src/query/` what a filter value means, `src/datetime/` the zone math and formatter (vectors in `test/fixtures/`), `src/units/` money and the shipped currency table.
- `src/glow/` highlights source to elements; its corpus is a committed snapshot of the css guide (`test/fixtures/guide-samples.json`, regenerated by `extract.mjs`). `src/predicate/` is the one kit split across files (`tokenize.js`, `parse.js`, `template.js`, `values.js`); `src/signature/seeded.js` makes a key pair from 32 bytes for `/signature` and `/seal` alike, reached by path and not an entry.
- `test/run.js` is the whole harness; `test/specs/` one spec per kit; `test/fixtures/` the vectors and the regenerators, each needing a dependency installed OUTSIDE this package.

## What bites here

The dozen that bite most; the full catalog is `docs/hazards.md`, read it before
touching datetime, json, units, sigv4, inflect or glow.

- **Every export is a pure function, and `scripts/ci.mjs` fails the build on a clock, a global, a network call or a non-relative import under `src/`.** `createStore` is NOT here and must not arrive (`FJS-D111`).
- **`/datetime`'s zone answers are the RUNTIME's, and node and bun differ.** Run the suite under both; a row failing under bun alone is dropped from the generator's `ZONES`, never special-cased.
- **`addToDate`'s clamp does not remember the day it came from.** A recurring date is computed from its ANCHOR each time.
- **A day is not 24 hours and `startOfDay` is not always midnight.** A day's window is `[startOfDay(d), startOfDay(d + 1 day))`.
- **An ISO string with no `Z` or offset is refused**, SQLite's `CURRENT_TIMESTAMP` shape included.
- **`/query`'s number rule is one line**: a string is a number only if `String(Number(v)) === v`.
- **A JSON member is an OWN property** — `__proto__` is legal JSON, so every `/json` rebuild goes through own-key definition, and every walker REFUSES past `MAX_DEPTH` (100).
- **`ctx.result` is an ACCESSOR and the value is not the test** — an `around` that never calls `next()` ends the pipeline with nothing run. `mergeHooks` answers a NEW map.
- **`formatMoney` is `Intl` over a SHIPPED currency table, the host's ICU is not asked** (`FJS-745`), and its amount is MAJOR units. `/sugar`'s `toCurrency` is that; `toMoney` is minor (`FJS-D1515`).
- **The sigv4 canonical string is six lines, the query is the third, and the scheme signs SECONDS** — a millisecond-shaped value is refused by name (`FJS-1001`): `now` THROWS, a header ANSWERS `{ok: false}`.
- **`inflect`'s `-ses` list and irregular table are DATA ABOUT ENGLISH**; a spelling sweep eats them, and a round trip is not a correctness test.
- **`directives` REPORTS the `$` names it does not know** rather than passing them on as filters (`FJS-988`).
- **A new subpath is invisible to a vite that is already running** — the exports map is read at server start.
- **A highlighter fails silently or not at all**, and glow's output is elements, never classes; `encode()` escapes `&` FIRST.

## Proving a change

`bun run test`, then the callers — a kit here is only correct in them:

| Changed | Run |
| --- | --- |
| `glow` | `packages/css`: `bun run test code` — it styles *real glow output*, injected by the css harness. A change to the element glow picks for a token breaks there, not here. Then `packages/mesa`: `bun run test`, whose markdown fences run it |
| `inflect` | `packages/litestone`: `bun run test` (table names), `packages/junction` and `packages/sierra`: `bun run test` (model resolution). A rule changed here renames tables — read the DDL snapshot diff before believing a green run |
| `datetime` | `packages/toolbelt`: `bun run test` AND `node test/run.js datetime` — the zone table is each runtime's own. A change to the inverse is graded by the vectors; regenerate them only when the ZONES or the window change, never to make a row pass |
| `units` | `packages/toolbelt`: `bun run test`, then `example`: `verify` and `verify:site` — the prices on a live screen and in a PRERENDERED file, which is the one place the formatter runs in node with no browser under it |
| `gate` | `packages/litestone`: `bun run test` (the boundary that enforces it) · `packages/junction`: `bun run test` — `session-gate-level.test.ts` asserts the export IS the kit's binding, which is the assertion four hand copies could not make · `packages/sierra`: `bun run test` (the screen's verdict). The kit's own spec walks the whole 216-case grid and the whole 0-9 square, because the drift was one branch and asking one grader about one caller is what hid it |
| `geo` | `packages/toolbelt`: `bun run test` — the spec compares `boundingBox`+`distance` against a BRUTE-FORCE scan at the equator, at a pole and across ±180, which is the only assertion that can see a prefilter dropping a row. Then `packages/litestone`: `bun test test/point.test.ts`, whose own gate is the same comparison in SQL: the two halves of a live list call `isNear` and the same haversine, so a change here moves the server's answer too |
| `match` | `packages/toolbelt`: `bun run test`, then `packages/sierra`: `bun run test` (the tether that reads it) and `packages/jetty`: `bun run test` (the other one, which may not import sierra). A `near` change is graded against litestone as well — `false` here REMOVES a row from a live list, so the two halves have to agree about a row on the circle's edge |
| `sse` | `packages/toolbelt`: `bun run test` — the spec reads every frame at every chunk boundary. Then `packages/sierra`: `bun run test event-stream`, which reads a REAL junction `ctx.sse()` stream through `readEvents` and asserts leaving the loop fires the server's `onDisconnect` |
| `frontmatter` | `packages/toolbelt`: `bun run test frontmatter`, then `packages/sierra`: `bun run test -- scanner` (the route table) and `packages/mesa`: `npx vitest run md-` (the `.md` module). A change to what the subset ADMITS is graded by `test/fixtures/frontmatter-compare.mjs` — js-yaml's core schema over every real block under the roots it is given (this repo, `fjs-prototypes`, the ksite client sites); the spec's rows are the cases somebody thought of |
| `textbox` | `packages/toolbelt`: `bun run test textbox` AND `node test/run.js textbox` — graphemes are the runtime's `Intl.Segmenter`, and Bun's `containing()` disagrees with node's, so the kit walks segments and the grapheme row is the one to watch under both |
| `textedit` | `packages/toolbelt`: `bun run test textedit`, then `packages/cli`: `bun test test/vite-ask.test.js` (the `/text` route over a real file) and `website`: `verify:ask`, which swaps a picked element's words in a browser |
| `directives` | `packages/junction`: `bun run test` — the bridge strips by this table, and `live-order.test.ts` asserts both transports only emit names it holds. Then `packages/sierra`: `bun run test` (`page-query.test.js`), and `example`: `verify` for a real navigation. **The orderBy pair has a third caller and a browser is the only place it runs**: `packages/ui`: `test:browser`, whose `Table — the modes` pushes the object and bracket-indexed shapes through the prop, each paired with a header that must stay unmarked |
