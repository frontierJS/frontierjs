# FrontierJS — Map

Bun-workspace monorepo: a schema-seeded fullstack framework. One mental model — three realms, three nouns:
**Data (Model) → API (Service) → UI (Resource)**, plus Deployment (Release) and Testing (Suite).
Everything derives from `db/schema.lite`; growth happens outward and traces back.

`ARCHITECT.md` §2 is the default vocabulary for design discussion. Depart from it when a different word is materially clearer — then fold the clearer word back in rather than keeping two.

## Evolution policy

FrontierJS is pre-alpha. **Prefer evolving existing designs over preserving them.** Existing behaviour is evidence, not a constraint.

Only two things are binding: the **Invariants** below, and rulings in `DECISIONS.md`. Everything else may change — prefer simplifying, removing duplication, and improving consistency over reproducing what is there. If you see a simpler design consistent with the architecture, propose it. **Preserve the mental model, not the mechanism.**

Where docs disagree, assume different stages of a pre-alpha design and reconcile, rather than treating either as wrong.

History lives in each package's `CHANGES.md` and `PROJECT_STATE.md`. Fixed bugs are recorded there, not here — this file is only what is live.

## Invariants

Don't violate without an explicit decision; record it in `DECISIONS.md` if you do.

1. **Dependency direction** — `Litestone ← Junction ← Sierra`, never reverse. Mesa is a leaf with zero workspace deps.
2. **Model names are PascalCase singular** (`model Lead` → `db.lead`); `@@external` exempt. Three resolvers depend on this agreeing.
3. **App layout** — `db/` + `api/` + `web/` at the root, most sub-project carry `config/ src/ public/ test/ dist/ deploy/` (db/ doesn't). Configuration lives in `config/`, `vite.config.js` included. Canonical: root `README.md` §Project Structure. Never *derive* a config path from where `vite.config.js` sits — probe, or be told.
4. **One owner per translation.** There is exactly one place that turns a thrown value into an HTTP status, one that wraps/unwraps the result envelope, one that parses `$`-params into `ctx.directives`, one that announces a mutation, one startup phase list every caller runs. Current implementations are in the bridge index. Add to the owner, never beside it.
5. **One owner per `app.<thing>`.** Claim it with `app.provide(name, value)`; type it by augmenting an exported interface, never by redeclaring the property (declaration merging requires identical types, so a redeclaration silently loses).
6. **Access is declared in the schema, not in hooks.** Gates, `@encrypted`, `@guarded`, `@@transitions` are enforced at the Data boundary. `x-gate` on the client is a UI affordance only — unknown answers are permissive and the server enforces regardless. No exceptions. *(`packages/basecamp` declares a level on all 37 models as of 2026-08-10. Its ladder is per WORKSPACE, so the level rides on the principal — `api/src/core/gate.ts` plus `applyStanding()`; `example/api/gate.ts` is the simpler case, where standing travels with the user. **Row-level tenancy is moving model by model**: `Server` declares `@@allow('all', workspaceId == auth().workspaceId)` as of 2026-08-10, the other 36 are still the service where-clause plus `scopeToWorkspace`.)*
7. **Protected fields are redacted in the audit trail.** `@encrypted`/`@guarded`/`@secret` values log as `[redacted]` in both field entries and `before`/`after` snapshots. Pinned by 8 tests in litestone.
8. **Caller-supplied names never enter a SQL pattern.** Metacharacters in an event name once fanned a webhook payload out to every subscription.
9. **Patch semantics: an explicit `null` clears.** Test key presence (`key in updates`), not `??`.
10. **`$` is transport syntax only.** `ctx.query` is filters, `ctx.directives` is `{limit, offset, orderBy, select}`; nothing past the bridge sees a `$`.
11. **The nearest delegation root owns an event.** Roots nest; a handler must fire once.
12. **Mesa compiler output is reproducible** — scope ids are content-addressed, which is also what makes CSS dedupe work across the two compilers a static build runs.
13. **`@frontierjs/css` is the styling language.** Style with a tone (`danger`) and a treatment (`outlined`), never a colour. **UnoCSS is supported alongside it, not instead of it** (ruled 2026-08-08) — an opt-in layer a consuming app configures; `packages/css/README.md` §Using it with UnoCSS is the measured configuration (layer position, the reset trap, three colliding names). A package in *this* repo still ships no utility classes: a component that needs Uno to look right cannot be used by an app that does not run it.
14. **Typecheck baselines ratchet down only.** Never raise one. They live in `scripts/typecheck-baselines.json`, one number per package, so that raising one is a visible diff; absent means 0 and clean. `bun run typecheck -- --update` writes an improvement back.
15. **A clean compile is not proof of valid JS.** Compiler tests check parseability. *(Applied to `fli` 2026-08-05: compiling all 195 command files and parsing the output found 14 producing broken JavaScript. Every command file now has a parse test.)*
16. **Runnable examples are verified, not sketches.** A broken one is a bug.
17. **At most four markdown files at a package root** — `README.md`, `CLAUDE.md`, `PROJECT_STATE.md`, `CHANGES.md`. Everything else in `<pkg>/docs/`.
18. **In a Sierra app, `src/resources/` holds `.mesa` files.** A Resource is a UI-realm noun, so it is written in the UI-realm language — not a `.js` file that happens to sit in the UI tree. A resource file has no markup; its code goes in `<script module>`, which runs once at import and whose named exports any other module can import (Mesa VISION §11, rule 30). Emission is identical to the `.js` it replaces — verified in `example/`, same chunk hash — so this is about the mental model staying one model, not about behaviour.
19. **A resource file is named for its noun — PascalCase, singular — one Resource per file.** `App.mesa`, not `apps.mesa`; the export inside stays the lowercase accessor (`export const apps`), exactly the split the Data realm already makes between `model App` and `db.app`. Where a model exists the filename IS the model name, which puts every irregular case in the filename where it is visible: `AlertRule.mesa` exporting `alerts` says out loud that regular pluralisation does not bridge those two, and that `model:` must therefore be stated. A resource over no model at all (`Portal.mesa`) takes its service noun, singularised. Ruled 2026-08-08 — see `DECISIONS.md`.

**Always `cd` into the package and run its own script.** Runners differ per
package and a wrong runner produces failures that belong to nothing.
`bun run --filter '*' test` from the root runs them all, correctly, one each.

**`bun run ci` is the whole of CI and it is not a GitHub feature.** One node
script runs four phases — hygiene, coverage, typecheck, tests — and
`.github/workflows/ci.yml` does nothing but call it, so it runs identically on a
laptop. It answers the questions the aggregate scripts cannot: a package with no
`test` script FAILS rather than being walked past in silence, a source file
`.gitignore` hides fails, a RAISED typecheck baseline fails (Invariant 14), and a
suite that is known to fail is named so a NEW failure is loud. Every allowance is
a named entry with a reason in `scripts/ci-allowances.json` — widening the net is
a diff, narrowing it is `--update`. `bun run hooks:install` points
`core.hooksPath` at `scripts/hooks`, whose `pre-push` runs the fast tier (~40s);
the suites (~3 min) belong in the workflow, because a pre-push that costs minutes
teaches everyone `--no-verify`. `--only <pkg>` narrows typecheck and tests to one
package.

`bun test` instead of `bun run test` runs bun's runner over whatever it finds —
in mesa that is ~35 failures that are runner artifacts, not defects.

**The browser drives need their servers started by hand, first.** They assert
against a running app and exit 1 with which process is missing if it is not
there. All of them need Chrome.

15 minutes across all of them** — a burst of drives fails as "broken app". Run
`verify` before `verify:ui` if you run both.

**Ports.** The scheme is `[env][category][project][service]` — documented in
`packages/jetty/src/dev/fjs-ports.js`, which owns extension dev ports (8400–8499
dev, 7400–7499 test).

| Port        | Who                                                            |
| ----------- | -------------------------------------------------------------- |
| 3600 / 3610 | `example` API / its dev mail sink                              |
| 5274        | `example` web (vite) — **and `basecamp` web, the same number** |
| 3001        | `basecamp` API                                                 |
| 3500 / 5273 | `packages/sierra/example` API / web                            |
| 5310        | `example`'s preview server, started by `verify:build`          |
| 5173        | `packages/css` demo (`$PORT` overrides)                        |

**`example` and `basecamp` cannot both serve their UI at once**, and only
basecamp says so: its vite config sets `strictPort` and `bun run dev` preflights
both ports. `example`'s does not — vite hops to the next free port silently, so
the drive then talks to whatever *is* on 5274. Check the port before starting.

**A dev server left running serves the code it started with.** A `.mesa` module
is transformed once and cached for the life of the process, so editing the
compiler invalidates nothing — start the server the run will test, and refuse a
port that already answers. Backgrounding a server from a tool call is unreliable
here (`nohup`/`setsid` both drop it); what works is a script that spawns it,
polls until it answers, asserts, and kills it — `example/web/test/verify-build.mjs`
is the shape.

## House style

Match the file you are in first; this is what the repo does when there is no
local precedent.

- **Comments explain the failure, not the mechanism.** Nearly every comment here
  is a bug that was paid for. Write why the shape is what it is and what breaks
  otherwise — `// increment the counter` is noise, `// vite hops ports silently,
  so the drive would talk to the other app` is the house voice.
- **A comment must be load-bearing. Delete it otherwise.** The test: if this
  comment vanished, could someone editing this file make a mistake it would have
  prevented? If no, it is not a comment — it is a changelog entry or an opinion,
  and both have somewhere else to live.
  - **No edit history in code.** "Used to be its own page", "merged 2026-08-08",
    "this replaced X", "before v0.6". That is `CHANGES.md`, `DECISIONS.md` and
    git. The one exception is narrow, and it is the whole reason the rule above
    says *failure*: a past bug stated because the shape still invites it
    (`--ring` in `tokens.css`), where the history IS the warning. "We
    reorganised this" is never that.
  - **No dates in code comments.** A date is a changelog's job. If the comment
    needs one to make sense it belongs in a decision record, and the code should
    point at that rather than restate it.
  - **No persuasion.** "they ARE it", "the whole point", "deliberately", "which
    is exactly why", italics for emphasis. Emphasis is not information. State
    the constraint flatly; if it needs selling, it needs a ruling in
    `DECISIONS.md` instead.
  - **Never narrate your own edit.** The reader does not know a change happened,
    is not the person you are arguing with, and did not ask.
- **Every non-trivial file opens with a header block** — what it is, and what it
  is *for* in a sentence or two. Test harnesses go further and document their own
  traps at the top (`example/web/test/verify.mjs`); that is where a trap gets
  read.
- **Section dividers inside a file**: `// ─── name ──────` (box-drawing, padded
  to a consistent width). Not `// ---`, not banner boxes.
- **Aligned columns** where a run of lines is parallel — imports, object
  literals, `const` blocks. See `example/api/app.ts`.
- **Prose in the docs is sentence-shaped, not bullet-shrapnel.** Bold the claim,
  then say what it cost. Numbers earn their place by being measured.
- **British spelling** in prose (`behaviour`, `serialise`). Identifiers stay US
  (`color`, `serialize`) where a web API or CSS property already chose.
- **No semicolons**, single quotes, 2-space indent — in TS and JS alike
  (`packages/css`'s own build/test scripts are the one holdout). TypeScript in
  junction, auth, caravan, conduit, notifications; plain ESM JavaScript in
  litestone, mesa, sierra, ui, css, jetty. Do not introduce TS into a JS package.
- **Fake clients hide real bugs.** Cross-package behaviour is tested against the
  real dependency, never a hand-rolled stand-in — `{ post: {…} }` passed every
  test and failed every real Litestone client.
- **A new defect gets an `FJS-###` in `ISSUES.md`**, not a paragraph in a
  package file. A ruling closes an `FJS-D##` and moves to `DECISIONS.md`.

## Live hazards

Things that will cost you time or break something *today*. Mostly **correct
behaviour you have to know about** — the things that are *wrong* are in
`ISSUES.md`, one id each. A hazard that turns out to be a defect belongs in both:
here so it does not bite, there so it gets fixed.

- **Run `bun run test` inside each package, not `bun test`** — runners differ, and the wrong one invents failures (~35 of them in mesa). §Running things above is the table, plus ports, drive prerequisites and which drive proves what.
- **A code sample highlighted with `prefix: true` loses its first character.** `glow()` treats a leading `+`, `-` or `>` as a diff/callout marker and REMOVES it — and in CSS all three are legal first characters (`--custom-prop`, `> .child`, `+ .sibling`). `--` is disambiguated (two dashes are never a marker); the combinators cannot be, so **a CSS caller passes `prefix: false`**, which is what the css guide does. Found by round-tripping the guide's 137 samples, where it corrupted exactly one — the kind of damage that looks like a typo in the docs rather than a bug in the tool.
- **`bun install` resolves `workspace:*` to a COPY under `node_modules/.bun/`, not a symlink.** An edit to `packages/mesa/src/compiler.js` is invisible to importers until reinstall, so a suite can go green against a stale snapshot. In-repo tests should import workspace source by relative path. `packages/ui`'s hand-made symlink will not survive a reinstall.
- **Raw routes (`app.get`/`app.post`):** path params are **`{id}`, not `:id`** — `:id` registers as a literal segment and 404s silently forever. `ctx` is `TransportContext`: `params` is path params only, headers are on `ctx.headers`.
- **A SERVICE context has no `ctx.params` at all** — verified at runtime (`'params' in ctx` → `false`; keys are `$raw app auth client data directives dispatch error id locals method model query result route service statusCode transport type`). It splits into `auth` (the principal) / `client` (`ip`, `userAgent`, **`headers`**) / `route` (path captures) / `locals` (per-call scratch, where `withLitestoneDb` puts `db`). **A raw-route `TransportContext` DOES have `params`** — that asymmetry is the whole trap, and Junction's own docs get it wrong: `core/app.ts:218`/`:224`/`:329` show `app.service('users').get(id, ctx.params)` and `core/litestone.ts:11` says the query tap is "cached on `ctx.params`" when the code writes `ctx.locals`. Stale Feathers idioms — **fix them, they cost real time**. Basecamp's services read `ctx.params.user.user_id` and `ctx.params.headers` throughout, every one `undefined`, so **role checks silently passed for everyone**. Also: `before: { all: [...] }` applies to *every* method including agent endpoints, and a comment claiming exemption is not one.
- **`hasRoute()` is a matching question, not an existence one** — every app registers `GET /{service}`, which matches almost anything. Use `hasExactRoute(method, path)` for "is this mounted", `routePaths(method)` for what landed where.
- **`createResource` now coerces, blank-strips and validates by default** (2026-08-06). A create that used to reach the server and 400 there now throws `ResourceValidationError` in the browser with the request never made, and an untouched text box writes NULL rather than `''`. Both are what every app in the repo was already asking for by hand — but a resource whose service deliberately accepts a shape the model does not describe now needs `{ validate: false }`, and the failure looks like "the button does nothing" if nothing renders the throw. `<Form>` renders it.
- **A Mesa component cannot expose a method.** `export function foo()` in an instance script is **dropped from the compiled output**, so `bind:this` methods documented in VISION §10.2 / RULE 36 do not exist — and a component that references its own exported function from its template throws `ReferenceError` on first interaction, which no render test can catch because SSR dispatches no events. `export let foo = () => {…}` is not the workaround: assignments inside a prop initialiser are not rewritten and the module does not parse. Hand the function out through a callback prop. `ISSUES.md` `FJS-087`.
- **An overlay that is present is not an overlay that is visible.** A kit
  overlay fades in with `el.animate(…, { fill: 'forwards' })` from an
  `{@attach}`, and until 2026-08-06 the attachment ran before the element was in
  the document, where that animation never starts: the palette, toasts and
  popovers were painted at keyframe 0 — invisible, and in the palette's case a
  full-screen backdrop that swallowed every click (`FJS-114`). Fixed in mesa,
  but the lesson stands for any drive: **assert computed opacity and
  hit-testing, not `querySelector`**. 26 assertions passed against an invisible
  palette for as long as it existed.
- **Mesa's scoped styles do not reach into child components.** Use `:global(...)`. (The selector subject carries the hash: `button` → `button.mHASH`.) Corollary, fixed 2026-08-04: **a dynamic `class` MERGES, it never replaces** — `set_attribute(el,'class',…)` wiped the scope class, so `<div class="card {theme}">` lost every style its own component declared for it, silently. All dynamic classes now route through `bindClassPassthrough`.
- **The audit logger defers one event-loop tick, so a read in the SAME tick sees 0 rows.** `fireLog()` schedules the write with `setImmediate` and the jsonl driver then appends synchronously — so anything after an `await` sees the row, and the fix is to yield once, not to wait. Not a bug; litestone's own examples read too early and report 0. There is no ~1s buffer and nothing flushes on exit, which is what this line used to say — a reader who waited a second and still saw nothing would have drawn exactly the wrong conclusion.
- **A `@@gate` refuses, a `@@allow` filters — so a wrong policy is an empty screen, not an error.** The two answer different questions (*may this caller touch Server at all* / *which servers*) and they fail in different registers: a gate throws naming the model and the level, a policy silently compiles into the WHERE. Which means **every read that legitimately crosses the policy's scope has to be `asSystem()`**, and one that is not returns nothing with a 200 — the same failure shape as `toDataPrincipal` and `FJS-117`. Declare one model at a time and run the app's drive between them. `basecamp`'s `Server` is the first, 2026-08-10; its engines, hub and agent endpoints were already `asSystem()`, which is the audit that has to come first. Related and now closed: an `include:` used to apply **no** access rule of the model it reached — not the policy, not the gate, not `@guarded` (`FJS-150`).
- **You cannot "run without gates". A schema declaring any `@@gate` auto-installs `GatePlugin({ getLevel: FrontierGateGetLevel })`** (`litestone/src/core/client.js` ~5688) — deliberate, since a declared-but-unenforced gate is fail-open. Installing your own GatePlugin replaces it; installing none does *not* disable it. **The resolver was fixed 2026-08-04** — it used to test `!user.verifiedAt`, collapsing "absent" into "null", so every session from an app without a verification flow graded `VISITOR(1)` (below the `USER(4)` an ordinary model needs to read) and gates 403'd the whole API. It now honours the documented contract: **absent = the app does not model this stage, not an objection; only `null` grades down** — and standing (`isSystemAdmin`/`isOwner`/`isAdmin`) is checked before the lifecycle, so a sysadmin with no role no longer grades `CREATOR(3)`. Verified: a `@frontierjs/auth` session now reads at `USER` through the auto-installed default while still being refused ADMIN writes. `sessionGateLevel()` in `packages/junction/src/core/litestone.ts` is the same function across the dependency boundary (Litestone cannot import Junction) — **a hand copy; change one, change both.**
- **Headless Chrome delivers almost no rendering lifecycle after load.** Anything behind `IntersectionObserver` must be set up before it; `requestAnimationFrame` hangs. Working pattern: `packages/sierra/tests/fixtures/island-site/verify.mjs`. **`getComputedStyle` also goes stale after a class change** — `el.matches()` and `document.styleSheets` report the new state while computed styles stay frozen at the pre-interaction values, and forcing layout does not help. To check a post-click style change, read the rules that match the element, not its computed style.
- **A running dev server does not notice that the compiler changed under it.** A `.mesa` module is transformed once and cached for the life of the process; editing `packages/mesa/src/compiler.js` invalidates nothing. A server left running from before a fix serves output from before the fix, and the app fails exactly as it did — which reads as "the fix did not work". Start the server the run will test, and refuse a port that is already answering. (Two independent sessions on this machine both wanted :5274; the second one silently tested the first one's app. `example/` and `basecamp` want that same port — see §Running things.)
- **Vite injects the built `<script>` at the first match for the body tag and does not skip comments.** `example/web/index.html` mentioned one inside a comment, so the injected tags landed *inside the comment*: `bun run build` succeeded, `dist/index.html` looked right, and the built page loaded no JavaScript with an empty console. Fixed there 2026-08-04 — but the trap is Vite's, so check any hand-written `index.html`. A build that succeeds is not a page that runs. **It happened a second time**: `packages/basecamp/web/index.html` had it too, found 2026-08-06 by screenshotting the build. Neither app's `verify` could see it, because both drive the *dev* server, where nothing is injected — so **no suite in this repo probes a production build** (FJS-085). Never write the body tag in a comment in an `index.html`.
- **Nested directories are invisible to the `packages/*` glob.** Invisible means uninstalled, untested, unrunnable. `mesa-vite/` was the case that mattered and it is closed the other way — it is no longer a package at all but a subpath of mesa, `@frontierjs/mesa/vite`, which is what a plugin whose only job is to call the compiler should always have been. What remains is `mesa-bench/` and `orion/mockup/api-engine`, both deliberate and both named in `scripts/ci-allowances.json`, so CI states them once rather than every run. (`packages/basecamp` was in this list until 2026-08-04; it now has a `package.json` and installs.)
- **`build/` was in `.gitignore`**, hiding 20 source files (Sierra's and jetty's build pipelines). Un-ignored, **still uncommitted**. Check any new ignore rule against `git status --porcelain`.
- **Publishing a package silences every loose peer range that names it — audit them on the way out.** While a sibling is unpublished, a peer of `"*"` or `>=0.1.0` fails at install with the name in the error; the moment it exists, the same range resolves from the registry without a word and keeps resolving through a future major. Junction going to npm on 2026-08-10 flipped five of them at once (notifications, jetty ×2, caravan, conduit), all now `^0.1.0`. **Below 1.0 a caret pins the MINOR** — `^0.1.0` is `>=0.1.0 <0.2.0` — which is the behaviour wanted for a pre-alpha peer and also the trap in the other direction: `@frontierjs/ui` declared `@frontierjs/css: ^0.11.0` against a css that had reached 0.15.0, so its declared peer excluded the only copies that exist. Nothing catches either shape from inside the workspace, because a `workspace:*` devDep answers first and the range is never consulted.
- **A Junction session is translated for the Data boundary — `toDataPrincipal()`.** `SessionContext` says `userId`, Litestone's policy language reads `auth().id`, and until 2026-08-06 nothing bridged them: every `@@allow('read', userId == auth().id)` compared a column to `undefined` and matched nothing, silently, for every signed-in caller. Gates were unaffected — `sessionGateLevel()` was written to Junction's shape — so an app with `@@gate` and no `@@allow` never noticed. **Two functions, one boundary, one direction**: change either and ask whether the other needs it too.
- **The audit log's `actorId` is `Any`, not `Int`.** Auth issues uuid ids; a STRICT INTEGER index column threw `cannot store TEXT value in INTEGER column` on the first audited write with a known actor and took the request with it. Fixed 2026-08-06 — and an index whose column types no longer match the schema is now dropped **and refilled from the `.jsonl`**, so a type change costs a rebuild rather than an audit trail that looks truncated.
- **A background job has no principal, and no principal is STRANGER(0).** `app.service('x').patch(…)` from a Caravan job or a scheduler defaults to `auth: { user: null }`, which the gate grades as anonymous — so a job writing back through the service is refused by the model's own `@@gate`. Pass one: `{ auth: { user: SYSTEM } }`, graded in the app's own `getLevel`. The alternative — `db.asSystem()` — writes at the Data boundary, where nothing announces (`FJS-010`) and every open tab keeps the stale row. `example/api/gate.ts` is the pattern.
- **Caravan's `unique` is a lock on work IN FLIGHT, not an idempotency key.** Once a job is terminal the key is free, so the same work can be queued again later. A key built from a row id is not an idempotency key either — SQLite reuses ids, so `book-courier:4` names two different orders months apart. Fixed 2026-08-06 (it used to disagree with its own schema in both directions, one way a raw `UNIQUE constraint failed` out of an HTTP request, the other a job that silently never ran); an old `jobs.db` is migrated on open.
- **An unknown query key over HTTP now answers 400, but the ORM still answers nothing.** `GET /api/products?bogusColumn=7` used to be `200 {"data":[],"total":0}` — a typo, a directive sent under the wrong name and a genuinely empty table all one answer; junction's `autoFilter` names every bad key instead since `FJS-109`. **Below the boundary the old behaviour stands**: a `where` typo on a `findMany` warns to stderr and returns no rows, so a service that builds its own filter still gets silence. `client.service('x').find({ limit: 100 })` is the trap that bites: the FIRST argument is the filter, `limit` belongs in the second — now a 400 naming the directives rather than an empty list. Also `find()` answers the list envelope — `findData()` is the rows.
- **A WebSocket frame can be DROPPED and nothing says so.** Bun's `ws.send()` answers `-1` for *buffered under backpressure* and **`0` for *discarded*** — past ~16.9MB of unacknowledged data on one socket (`maxBackpressureLimit` is accepted and ignored, measured on 1.3.11). Junction ignored that number at every send site until 2026-08-10, so a dropped `service_result` left the caller pending until its own 30s timeout — no error, no close, nothing logged — and a dropped `event` frame left every open tab quietly stale. **`transport/outbox.ts` is now the one owner of a send**: it holds a dropped frame, flushes on `drain`, queues everything behind a held frame so order survives, and past `http.wsMaxQueued` (8MB) closes the socket with 1013 so the client rejects its in-flight calls and reconnects. Never call `ws.send()` directly (`FJS-145`).
- **The METHOD decides list vs single, and `find` is the only one that promises a list.** `wrapResult` used to decide by shape alone: any `{ data, total }` was rebuilt as a paginated list from `total`/`limit`/`offset`/`data`/`errors`, whatever produced it. Two silent failures out of one guess, both closed 2026-08-10. A custom action answering rows **plus** a summary lost the summary — 200, no warning, and a picker offering widgets it could not fill in (`FJS-140`). A `find` answering ONE object was wrapped as a `single`, which the browser client then read as an EMPTY list — a screen rendering nothing while the API was correct, visible only from a browser (`FJS-144`). Now: **`find` → a list or `ResultShapeError`** (naming the service, what arrived, and the keys that have no home), an array → a list, the bulk `{data,errors}` protocol → a list on any method, **everything else → a single, which travels whole**. Same function runs on both sides of the wire — the browser client asks it of what arrived instead of carrying a copy of the rule. A service answering one thing gives it a name and calls it as an action; a summary alongside rows is its own action.
- **A Litestone client THROWS on an unknown property — it never answers `undefined`.** Deliberate, so a typo'd accessor is loud rather than a silent `undefined.findMany`. The cost is that **feature-detecting a method is itself a throwing expression**: `typeof db.$maybe === 'function'` does not test, it explodes. Probe inside a `try`, or ask `'$maybe' in db`. This is not theoretical — `$checkWhere` was added to the root proxy only, so `typeof ctx.locals.db.$checkWhere` took down every list read by a signed-in caller in **both** apps, and the browser symptom was that redirects stopped committing (`FJS-117`). A capability that depends only on the schema belongs on every flavour of client: root, `$setAuth`, `asSystem`, `$scopedBy`.
- **Litestone emits columns verbatim camelCase and `DateTime` as ISO-8601 TEXT.** Hand-written SQL that assumed snake_case or epoch-ms integers will not match.
- **`createClient({ db })` is silently ignored when the schema declares `database main`** — the declaration wins. `db: ':memory:'` then writes the declared file path and says nothing, so a test that believes it is in-memory accumulates state across runs.
- **A wire-only field must be captured in a BEFORE hook, not in the method body.** `autoValidate` deletes every key the model does not declare, and Junction runs user hooks BEFORE the derived ones — so by the time a method body reads `ctx.data`, a field that is not a column is gone. Silent: basecamp's channels service answered *Slack needs a credential — send it as `secret`* about a request carrying exactly that. Same shape as `ip_address` on the servers service, where the write succeeds and the column comes back null.
- **A JSON Schema `default` is now parsed for array and `Json` fields.** `tags String[] @default("[]")` used to reach the boundary as `{"type":"array","default":"[]"}` — a schema whose own default failed its own type check, so `autoValidate` filled it in and then refused it: every create that OMITTED the field 400'd naming a field the caller never sent, while sending `tags: []` explicitly worked (`FJS-120`). The parse is keyed on the FIELD's type, so a `String` column defaulting to the two characters `[]` still means those two characters.
- **Raw SQL requires `asSystem()` once a schema declares access rules.** `db.sql` and `db.$setAuth(u).sql` both throw; `db.asSystem().sql` is the bypass — and it can WRITE, which it could not until 2026-08-08: every raw statement ran on the readonly connection, so the documented escape hatch failed with `SQLITE_READONLY` on anything but a SELECT (`FJS-118`). Raw statements enforce no `@@gate`/`@@allow`/`@guarded`/`@scoped`/`@@softDelete` — all of those live above SQLite — and the two `sql` functions used to be byte-identical, so a scoped caller silently got every row and every guarded column. Coarse per schema on purpose: deciding per statement means parsing it, and a wrong SQL validator grants a *false* guarantee (`bun:sqlite` exposes no authorizer). `where: { $raw: sql\`…\` }` keeps every policy and is the escape hatch to reach for. **A JS migration is exempt** — the runner hands it the system client, because a migration is schema surgery outside any request. Ruled in `DECISIONS.md`; scoped raw SQL (`IDEAS/scoped-sql.md`) is deliberately unbuilt.
- **Junction resolves every Bearer token through `IAuth.verifySession()` and calls `verifyApiKey` nowhere.** One door, `transport/http.ts:385`. So an API key is only ever verified if the *provider* falls through to its own `verifyApiKey` — better-auth's does, and `@frontierjs/auth`'s did not until 2026-08-09, which meant `createApiKey()` succeeded and every request carrying the token it returned was anonymous. A key that can be issued and never used, failing as *unauthenticated* rather than as *not a key*. A third provider inherits that job. Related: a `SessionContext` from a key now carries `scopes` (absent, not `[]`, when none were issued) and `credentialId` — without the latter two keys on one user produce identical sessions, so nothing can record per-key usage or hold one key to a limit the other does not have.
- **A required column only the server can fill cannot be created from the browser.** `createResource` validates by default, so a model whose create schema requires a system-written column refuses every create *before the request is made*, naming fields the caller was never meant to send — and the symptom is "the button does nothing". Basecamp's `ApiKey` is `required: ["workspaceId","userId","name","tokenHint"]` with three of four server-side. The only escape today is `{ validate: false }`, which turns a whole resource off to describe three columns; nothing in the schema can say *the system writes this* (`FJS-095`, ruling `FJS-D22`).
- **`$setAuth(user)` RETURNS a scoped client, it does not mutate.** `db.$setAuth(u)` followed by `db.thing.create(…)` grades as anonymous — `getLevel` receives `null` — with no warning. It is `const userDb = db.$setAuth(u)`.
- **`@guarded` is not a level** — it is a system-context lock taking only `(all)`, and `@guarded(5)` does not parse. Per-role read access to a column is field-level `@allow('read', auth().role == 'admin')`.
- **`encryptionKey` is parsed as hex**, so a 64-*character* key is not necessarily a 32-byte one. Non-hex padding decodes short and is rejected with `must be 32 bytes (got 1)`.
- Line numbers in `drift-report.md` reflect the 2026-07-31 tree — verify before citing.

## Bridge index — the named cross-package handoffs

The current seams. Reach for them before grepping. They may move, merge, or change signature as long as ownership and dependency direction hold.

**Data → API**
- `$setAuth(user)` / `asSystem()` — the Data-boundary checkpoint / bypass — `litestone/src/core/client.js`
- `withLitestoneDb(db)` — per-request scoped client on `ctx.locals.db`; auto-installed by `createApp({ db })` — `junction/src/core/litestone.ts`
- `gateAuth()` + `autoValidate()` — schema-derived 401s/400s for model services — `junction/src/core/litestone.ts` + `core/service.ts`
- `sessionGateLevel(user)` — `SessionContext` → litestone's 0–7 scale; pass to `GatePlugin({ getLevel })`. Litestone's own default grades a shape Junction does not produce
- `toDataPrincipal(user)` — the OTHER half of the same translation: `SessionContext` → the principal litestone's `auth()` reads (`userId` → `id`). Applied at both `$setAuth` call sites. Without it every row policy matches nothing and nothing says so
- `accessorCandidates()` — `model Post` ⇄ service `posts` ⇄ `db.post`; shared by query, gate and validation so a naming slip can't disable just one
- `db.$checkWhere(accessor, where)` → `[{key, suggestion, allowed}]` — **the one definition of "is this a valid filter key"**, asked rather than copied. Litestone's ORM behaviour is warn-on-read / throw-on-write; a boundary that can answer 400 calls this first instead, and junction's `autoFilter` derived hook does. No warning, no query, and an unknown accessor answers `[]` — *I cannot judge this* is not *this is wrong*. **On every flavour of client** (root, `$setAuth`, `asSystem`, `$scopedBy`), identically: filterability is a fact about the schema, and auth has no bearing on it. It was root-only for a day and that broke both apps — `FJS-117`

**Schema → API/UI**
- `generateJsonSchema(schema)` — consumed by junction validation and sierra's `build/schema-plugin.js` → `registerSchemas(defs, modelNames)`. **`$defs` is the whole definition table** (models, enums, `type T`, FileRef) and must stay whole — enum fields emit `{"$ref":"#/$defs/Plan"}` and both sides resolve it. Model names travel separately. **`packages/litestone/docs/jsonschema.md` is the full key reference** — every keyword and every `x-` it can emit, which mode/audience produces it, and who reads it (five extensions currently have no reader)
- `@label` → `title` and validator messages → **`x-messages`**, keyed by rule name *and* by the JSON Schema keyword it compiles to. Litestone owns the keyword table (`jsonschema.js`); Junction's `schema.ts` and Sierra's `field-rules.js` each just look up the keyword they failed. A field's label is read off the field's OWN schema, never a `$ref` target — enum `$def`s are titled with the type name
- `buildFieldRules()` / `validateAgainstFields()` / `coerceToSchema()` / `normalizeBlanks()` — `sierra/src/junction/field-rules.js`, deliberately a **leaf module** with no Junction-client import, so it runs in plain Node and can be compared against junction's server rules rather than a copy. Pipeline order is **coerce → blankToNull → validate**. All three ON by default on `createResource` as of 2026-08-06 (`{ validate: false }` opts out; the test is `!== false`, so a threaded-through `undefined` does not disarm it)
- `toFieldErrors(err)` — same module, also `resource.fieldErrors(err)`. **The one owner of "a thrown value → per-field messages."** Three shapes reach it because each hop wraps once: `err.errors` (ResourceValidationError), `err.data.data` (a server 400 through the browser client — the double `data` is real, both transports produce it), `err.data` (one shallower). Returns `{ fields, message }`; `message` is empty when the failure was entirely per-field. `@frontierjs/ui`'s `<Form>` calls it and knows nothing else about error shapes
- `$context.form` — **the UI-side form seam**, provided by `ui/components/forms/Form.mesa` as `{ errors, submitting, disabled, fields, submitted }`. Nine controls consume it to resolve their own label, constraints, `aria-invalid` and message; an absent form reads `undefined` and every fallback is what the control did standing alone. A stated prop always wins, including `required={false}`
- `buildRelations()` / `buildGate()` / `canAtLevel()` — same module. **`x-relations` is the only place a relation exists on the client**; `x-gate` is an affordance, never a boundary
- **`x-version`** — names the `@version` column an update must carry back, plus `readOnly` on that field in the update schema and absent from the create schema. `buildVersion()` reads it; `createResource` remembers the version of every record it reads and puts it on the next patch, so an app writes nothing. A stated version still wins. `resource.version(id)` / `.versionField` expose it
- **`retryable` on a thrown error** — the one thing a status cannot carry. A 409 is a race (`VersionConflictError`, `TransitionConflictError` — re-read and re-apply) or a domain refusal (`TransitionViolationError` — show its own message), and only the flag separates them. Set it on any error class you own; `toFrameworkError` adopts it and `FrameworkError.toJSON` puts it on the wire, where both transports land it at `err.data.retryable`. `isStaleWrite(err)` is the client-side reader and `toFieldErrors` turns a true into a sentence
- `buildTransitions()` / `transitionsAt()` — same module. `@@transitions` reaches the client as **`x-transitions` on the model, keyed by field** — never on the enum `$def`, because only a model can carry a per-transition `@gate` and two sources would drift. Mirrors litestone's `db.<model>.transitions(row)` field for field; `allowed` is an affordance on the same permissive contract as `canAtLevel()`
- `modelNameFor()` / `schemaFor()` — `sierra/src/junction/schema-registry.js`. Regular English plurals only; irregulars need `createResource('people', { model: 'Person' })`. A miss warns and degrades to a bare `make()`
- `authSchemaFragments(db)` — auth contributes INTO the seed — `auth/schema.ts`. The CLI's `auth/install.md` is a hand-copy: change one, change both

**API internals**
- `bridge.toContext()` / `toResponse()` — the transport↔service boundary — `junction/src/transport/bridge.ts`
- `toFrameworkError()` — the error boundary. Order: `FrameworkError` → `registerErrorMapper(fn)` → numeric `status`/`statusCode`/`code` in 400–599 → `err.name` → 500. **If you own the error class, give it a `status`** — no registration, no Junction dependency. `registerErrorMapper` is for errors you can't modify
- `wrapResult(raw, service, method)` / `unwrapResult()` / `isServiceResult()` — the result envelope. `kind:'single'|'list'` discriminates; a list keeps its envelope, a single unwraps. **The method decides the kind** — `find` must answer a list or it throws `ResultShapeError`; the browser client calls the same function rather than copying the rule
- `ctx.directives` — parsed from `$`-params by the bridge and nothing else
- Plugin protocol `{ name, register, boot, ready, shutdown, requires }` — `junction/src/core/app.ts`. **`register` is sync** (`configure()` never awaits it) — async setup goes in `boot()`. `requires: ['mailer']` is checked once at startup against presence *and* configure order
- `runStartPhases(bindHost)` — the one startup list; `needsHost` phases are skipped by the test path
- `IAuth.verifySession(token)` — inbound auth — declared `junction/src/auth/types.ts`, implemented `auth/auth.ts`
- `createLitestoneAuth(db, { sessionFields })` — **the one place an app's OWN `User` columns reach the session.** auth owns `model User` and every app extends it; `sessionFields(user)` is called from `toContext()`, the single point every issued session is built, so one hook covers login, `verifySession`, an API key and `createUser`. Two kinds of thing belong in it: the standing `sessionGateLevel()` grades on (`isAdmin`/`isOwner`/`isSystemAdmin`/`activatedAt`/`verifiedAt`), which is how an app whose privileged bit is its own column reaches `@@gate` at all, and the app's own keys, which travel untouched. Spread LAST — an app that states a field wins. The alternative it replaces is a wrapper around `verifySession` that re-reads the user: a third query on the hottest path, for a row auth already has
- `manifestPlugin()` + litestone `status()` — migration state into `/manifest`

**API → UI**
- `wsSend()` / `flushOutbox()` — `junction/src/transport/outbox.ts`. **The one owner of "put this frame on that socket"**, both for replies and for broadcasts. Bun drops a frame under backpressure and returns 0; this holds it and re-sends on drain
- `publish()` hook + `app.channel(name)` — real-time — `junction/src/transport/channels.ts`. Services declare `channel: 'posts'`; `callService` is the single announcement point for both the bus (`svc:created`) and channels (`svc created`). **A custom action announces too, under its own name** (`orders pay`) as of 2026-08-06 — it did not until then, so an action changed a row and told nobody, and every app masked it by refetching after the call. Only `find`/`get` are excluded; a read-shaped action opts out with `ctx.dispatch = false`. Open: litestone `onEvent` has no Junction subscriber; jetty hardcodes Feathers-style names
- **Transport: WebSocket is the default when one is connected, HTTP is the fallback.** Every service call — CRUD *and* custom actions — checks `_wsReady` first; over WS it is a `service_call` frame naming the method, over HTTP it is the REST verb (custom actions: `POST /{service}/{id}` + `X-Service-Method`). The one documented exception is a payload carrying a File: multipart cannot travel over the socket. **A custom action may address the COLLECTION** — `action(name, null, data, query)` posts to `/{service}` rather than `/{service}/{id}`, which the bridge has always accepted (it dispatches on the header before it looks at `params.id`) and neither client could express until 2026-08-08 (`FJS-122`). Stated in `junction/README.md`; `action`/`restore` ignored it until 2026-08-04
- `createJunctionClient()` / `client.resource(name)` — `junction/src/client/index.ts`, consumed at `sierra/src/junction/index.js`

**UI**
- `watchProxy()` / `createSignal()` / `createRoot(fn)` — the reactive seam and lifetime ownership — `mesa/runtime.js`
- `mount(label, Component, {props, root})` — page entry. Registers the delegation root; a component called directly renders but handles no events
- `renderComponent(src, opts)` — UI → HTML at build time; Sierra's `static` target composes route + layout chain through it. Children must be supplied **both** ways (`children={s}` and element children) — the two slot protocols don't bridge
- `island(anchor, Comp, props, block, meta)` — the island seam, off by default. Markers are **comments, not an element** (an element is foster-parented out of `<tbody>` and joins `>` selectors). Sierra collects them at prerender, bundles one chunk per island, and mounts via `@frontierjs/sierra/islands`. **A mounted ancestor is authoritative** — nested islands render live before their directives fire; test a marker with `isConnected`, not `parentNode`
- `externalSignals` — sierra tells mesa which imports are reactive — `sierra/src/build/mesa-plugin.js`. Hand-maintained; slated for retirement
