# FrontierJS — Map

Bun-workspace monorepo: a schema-seeded fullstack framework. One mental model — three realms, three nouns:
**Data (Model) → API (Service) → UI (Resource)**, plus Deployment (Release) and Testing (Suite).
Everything derives from `db/schema.lite`; growth happens outward and traces back.

`ARCHITECT.md` §2 is the default vocabulary for design discussion. Depart from it when a different word is materially clearer — then fold the clearer word back in rather than keeping two.

## Evolution policy

FrontierJS is pre-alpha. **Prefer evolving existing designs over preserving them.** Existing behaviour is evidence, not a constraint.

Only two things are binding: the **Invariants** below, and rulings in `DECISIONS.md`. Everything else may change — prefer simplifying, removing duplication, and improving consistency over reproducing what is there. If you see a simpler design consistent with the architecture, propose it. **Preserve the mental model, not the mechanism.**

Where docs disagree, assume different stages of a pre-alpha design and reconcile, rather than treating either as wrong.

History lives in each package's `CHANGES.md` and `PROJECT_STATE.md`. Fixed bugs are recorded there, not here — this file is only what is live.

## Invariants

Don't violate without an explicit decision; record it in `DECISIONS.md` if you do.

1. **Dependency direction** — `Litestone ← Junction ← Sierra`, never reverse. Mesa is a leaf with zero workspace deps.
2. **Model names are PascalCase singular** (`model Lead` → `db.lead`); `@@external` exempt. Three resolvers depend on this agreeing.
3. **App layout** — `db/` + `api/` + `web/` at the root, most sub-project carry `config/ src/ public/ test/ dist/ deploy/` (db/ doesn't). Configuration lives in `config/`, `vite.config.js` included. Canonical: root `README.md` §Project Structure. Never *derive* a config path from where `vite.config.js` sits — probe, or be told.
4. **One owner per translation.** There is exactly one place that turns a thrown value into an HTTP status, one that wraps/unwraps the result envelope, one that parses `$`-params into `ctx.directives`, one that announces a mutation, one startup phase list every caller runs. Current implementations are in the bridge index. Add to the owner, never beside it.
5. **One owner per `app.<thing>`.** Claim it with `app.provide(name, value)`; type it by augmenting an exported interface, never by redeclaring the property (declaration merging requires identical types, so a redeclaration silently loses).
6. **Access is declared in the schema, not in hooks.** Gates, `@encrypted`, `@guarded`, `@@transitions` are enforced at the Data boundary. `x-gate` on the client is a UI affordance only — unknown answers are permissive and the server enforces regardless. No exceptions. *(`packages/basecamp` currently declares no `@@gate` and grades in service hooks — that is outstanding work against this invariant, not a licence. `example/api/gate.ts` is the pattern it needs.)*
7. **Protected fields are redacted in the audit trail.** `@encrypted`/`@guarded`/`@secret` values log as `[redacted]` in both field entries and `before`/`after` snapshots. Pinned by 8 tests in litestone.
8. **Caller-supplied names never enter a SQL pattern.** Metacharacters in an event name once fanned a webhook payload out to every subscription.
9. **Patch semantics: an explicit `null` clears.** Test key presence (`key in updates`), not `??`.
10. **`$` is transport syntax only.** `ctx.query` is filters, `ctx.directives` is `{limit, offset, orderBy, select}`; nothing past the bridge sees a `$`.
11. **The nearest delegation root owns an event.** Roots nest; a handler must fire once.
12. **Mesa compiler output is reproducible** — scope ids are content-addressed, which is also what makes CSS dedupe work across the two compilers a static build runs.
13. **`@frontierjs/css` is the styling language.** No UnoCSS, no utility classes, anywhere. Style with a tone (`danger`) and a treatment (`outlined`), not a colour.
14. **Typecheck baselines ratchet down only.** Never raise one.
15. **A clean compile is not proof of valid JS.** Compiler tests check parseability. *(Applied to `fli` 2026-08-05: compiling all 195 command files and parsing the output found 14 producing broken JavaScript. Every command file now has a parse test.)*
16. **Runnable examples are verified, not sketches.** A broken one is a bug.
17. **At most four markdown files at a package root** — `README.md`, `CLAUDE.md`, `PROJECT_STATE.md`, `CHANGES.md`. Everything else in `<pkg>/docs/`.
18. **In a Sierra app, `src/resources/` holds `.mesa` files.** A Resource is a UI-realm noun, so it is written in the UI-realm language — not a `.js` file that happens to sit in the UI tree. A resource file has no markup; its code goes in `<script module>`, which runs once at import and whose named exports any other module can import (Mesa VISION §11, rule 30). Emission is identical to the `.js` it replaces — verified in `example/`, same chunk hash — so this is about the mental model staying one model, not about behaviour.

## Live hazards

Things that will cost you time or break something *today*. Mostly **correct
behaviour you have to know about** — the things that are *wrong* are in
`ISSUES.md`, one id each. A hazard that turns out to be a defect belongs in both:
here so it does not bite, there so it gets fixed.

- **Run `bun run test` inside each package, not `bun test`.** Runners differ: mesa and sierra are vitest, jetty is plain `node`, css drives headless Chrome (needs Chrome/Chromium on PATH or `FJS_CHROME`), everything else is bun. `bun test` in mesa reports ~35 failures that are runner artifacts.
- **`bun install` resolves `workspace:*` to a COPY under `node_modules/.bun/`, not a symlink.** An edit to `packages/mesa/src/compiler.js` is invisible to importers until reinstall, so a suite can go green against a stale snapshot. In-repo tests should import workspace source by relative path. `packages/ui`'s hand-made symlink will not survive a reinstall.
- **Raw routes (`app.get`/`app.post`):** path params are **`{id}`, not `:id`** — `:id` registers as a literal segment and 404s silently forever. `ctx` is `TransportContext`: `params` is path params only, headers are on `ctx.headers`.
- **A SERVICE context has no `ctx.params` at all** — verified at runtime (`'params' in ctx` → `false`; keys are `$raw app auth client data directives dispatch error id locals method model query result route service statusCode transport type`). It splits into `auth` (the principal) / `client` (`ip`, `userAgent`, **`headers`**) / `route` (path captures) / `locals` (per-call scratch, where `withLitestoneDb` puts `db`). **A raw-route `TransportContext` DOES have `params`** — that asymmetry is the whole trap, and Junction's own docs get it wrong: `core/app.ts:218`/`:224`/`:329` show `app.service('users').get(id, ctx.params)` and `core/litestone.ts:11` says the query tap is "cached on `ctx.params`" when the code writes `ctx.locals`. Stale Feathers idioms — **fix them, they cost real time**. Basecamp's services read `ctx.params.user.user_id` and `ctx.params.headers` throughout, every one `undefined`, so **role checks silently passed for everyone**. Also: `before: { all: [...] }` applies to *every* method including agent endpoints, and a comment claiming exemption is not one.
- **`hasRoute()` is a matching question, not an existence one** — every app registers `GET /{service}`, which matches almost anything. Use `hasExactRoute(method, path)` for "is this mounted", `routePaths(method)` for what landed where.
- **`createResource` now coerces, blank-strips and validates by default** (2026-08-06). A create that used to reach the server and 400 there now throws `ResourceValidationError` in the browser with the request never made, and an untouched text box writes NULL rather than `''`. Both are what every app in the repo was already asking for by hand — but a resource whose service deliberately accepts a shape the model does not describe now needs `{ validate: false }`, and the failure looks like "the button does nothing" if nothing renders the throw. `<Form>` renders it.
- **A Mesa component cannot expose a method.** `export function foo()` in an instance script is **dropped from the compiled output**, so `bind:this` methods documented in VISION §10.2 / RULE 36 do not exist — and a component that references its own exported function from its template throws `ReferenceError` on first interaction, which no render test can catch because SSR dispatches no events. `export let foo = () => {…}` is not the workaround: assignments inside a prop initialiser are not rewritten and the module does not parse. Hand the function out through a callback prop. `ISSUES.md` `FJS-087`.
- **Mesa's scoped styles do not reach into child components.** Use `:global(...)`. (The selector subject carries the hash: `button` → `button.mHASH`.) Corollary, fixed 2026-08-04: **a dynamic `class` MERGES, it never replaces** — `set_attribute(el,'class',…)` wiped the scope class, so `<div class="card {theme}">` lost every style its own component declared for it, silently. All dynamic classes now route through `bindClassPassthrough`.
- **The audit logger buffers ~1s and flushes on exit**, so a read straight after a write returns 0 rows and the `.jsonl` may not exist yet. Not a bug — litestone's own examples read too early and report 0. Logger `path` resolves relative to process CWD, not the schema file.
- **You cannot "run without gates". A schema declaring any `@@gate` auto-installs `GatePlugin({ getLevel: FrontierGateGetLevel })`** (`litestone/src/core/client.js` ~5688) — deliberate, since a declared-but-unenforced gate is fail-open. Installing your own GatePlugin replaces it; installing none does *not* disable it. **The resolver was fixed 2026-08-04** — it used to test `!user.verifiedAt`, collapsing "absent" into "null", so every session from an app without a verification flow graded `VISITOR(1)` (below the `USER(4)` an ordinary model needs to read) and gates 403'd the whole API. It now honours the documented contract: **absent = the app does not model this stage, not an objection; only `null` grades down** — and standing (`isSystemAdmin`/`isOwner`/`isAdmin`) is checked before the lifecycle, so a sysadmin with no role no longer grades `CREATOR(3)`. Verified: a `@frontierjs/auth` session now reads at `USER` through the auto-installed default while still being refused ADMIN writes. `sessionGateLevel()` in `packages/junction/src/core/litestone.ts` is the same function across the dependency boundary (Litestone cannot import Junction) — **a hand copy; change one, change both.**
- **Headless Chrome delivers almost no rendering lifecycle after load.** Anything behind `IntersectionObserver` must be set up before it; `requestAnimationFrame` hangs. Working pattern: `packages/sierra/tests/fixtures/island-site/verify.mjs`. **`getComputedStyle` also goes stale after a class change** — `el.matches()` and `document.styleSheets` report the new state while computed styles stay frozen at the pre-interaction values, and forcing layout does not help. To check a post-click style change, read the rules that match the element, not its computed style.
- **A running dev server does not notice that the compiler changed under it.** A `.mesa` module is transformed once and cached for the life of the process; editing `packages/mesa/src/compiler.js` invalidates nothing. A server left running from before a fix serves output from before the fix, and the app fails exactly as it did — which reads as "the fix did not work". Start the server the run will test, and refuse a port that is already answering. (Two independent sessions on this machine both wanted :5274; the second one silently tested the first one's app.)
- **Vite injects the built `<script>` at the first match for the body tag and does not skip comments.** `example/web/index.html` mentioned one inside a comment, so the injected tags landed *inside the comment*: `bun run build` succeeded, `dist/index.html` looked right, and the built page loaded no JavaScript with an empty console. Fixed there 2026-08-04 — but the trap is Vite's, so check any hand-written `index.html`. A build that succeeds is not a page that runs. **It happened a second time**: `packages/basecamp/web/index.html` had it too, found 2026-08-06 by screenshotting the build. Neither app's `verify` could see it, because both drive the *dev* server, where nothing is injected — so **no suite in this repo probes a production build** (FJS-085). Never write the body tag in a comment in an `index.html`.
- **Nested directories are invisible to the `packages/*` glob** — `mesa-vite/` and `mesa-bench/` inside `packages/mesa`. Invisible means uninstalled, untested, unrunnable. (`packages/basecamp` was in this list until 2026-08-04; it now has a `package.json` and installs.)
- **`build/` was in `.gitignore`**, hiding 20 source files (Sierra's and jetty's build pipelines). Un-ignored, **still uncommitted**. Check any new ignore rule against `git status --porcelain`.
- **A Junction session is translated for the Data boundary — `toDataPrincipal()`.** `SessionContext` says `userId`, Litestone's policy language reads `auth().id`, and until 2026-08-06 nothing bridged them: every `@@allow('read', userId == auth().id)` compared a column to `undefined` and matched nothing, silently, for every signed-in caller. Gates were unaffected — `sessionGateLevel()` was written to Junction's shape — so an app with `@@gate` and no `@@allow` never noticed. **Two functions, one boundary, one direction**: change either and ask whether the other needs it too.
- **The audit log's `actorId` is `Any`, not `Int`.** Auth issues uuid ids; a STRICT INTEGER index column threw `cannot store TEXT value in INTEGER column` on the first audited write with a known actor and took the request with it. Fixed 2026-08-06 — and an index whose column types no longer match the schema is now dropped **and refilled from the `.jsonl`**, so a type change costs a rebuild rather than an audit trail that looks truncated.
- **A background job has no principal, and no principal is STRANGER(0).** `app.service('x').patch(…)` from a Caravan job or a scheduler defaults to `auth: { user: null }`, which the gate grades as anonymous — so a job writing back through the service is refused by the model's own `@@gate`. Pass one: `{ auth: { user: SYSTEM } }`, graded in the app's own `getLevel`. The alternative — `db.asSystem()` — writes at the Data boundary, where nothing announces (`FJS-010`) and every open tab keeps the stale row. `example/api/gate.ts` is the pattern.
- **Caravan's `unique` is a lock on work IN FLIGHT, not an idempotency key.** Once a job is terminal the key is free, so the same work can be queued again later. A key built from a row id is not an idempotency key either — SQLite reuses ids, so `book-courier:4` names two different orders months apart. Fixed 2026-08-06 (it used to disagree with its own schema in both directions, one way a raw `UNIQUE constraint failed` out of an HTTP request, the other a job that silently never ran); an old `jobs.db` is migrated on open.
- **Litestone emits columns verbatim camelCase and `DateTime` as ISO-8601 TEXT.** Hand-written SQL that assumed snake_case or epoch-ms integers will not match.
- **`createClient({ db })` is silently ignored when the schema declares `database main`** — the declaration wins. `db: ':memory:'` then writes the declared file path and says nothing, so a test that believes it is in-memory accumulates state across runs.
- **Raw SQL requires `asSystem()` once a schema declares access rules.** `db.sql` and `db.$setAuth(u).sql` both throw; `db.asSystem().sql` is the bypass. Raw statements enforce no `@@gate`/`@@allow`/`@guarded`/`@scoped`/`@@softDelete` — all of those live above SQLite — and the two `sql` functions used to be byte-identical, so a scoped caller silently got every row and every guarded column. Coarse per schema on purpose: deciding per statement means parsing it, and a wrong SQL validator grants a *false* guarantee (`bun:sqlite` exposes no authorizer). `where: { $raw: sql\`…\` }` keeps every policy and is the escape hatch to reach for. **A JS migration is exempt** — the runner hands it the system client, because a migration is schema surgery outside any request. Ruled in `DECISIONS.md`; scoped raw SQL (`IDEAS/scoped-sql.md`) is deliberately unbuilt.
- **`$setAuth(user)` RETURNS a scoped client, it does not mutate.** `db.$setAuth(u)` followed by `db.thing.create(…)` grades as anonymous — `getLevel` receives `null` — with no warning. It is `const userDb = db.$setAuth(u)`.
- **`@guarded` is not a level** — it is a system-context lock taking only `(all)`, and `@guarded(5)` does not parse. Per-role read access to a column is field-level `@allow('read', auth().role == 'admin')`.
- **`encryptionKey` is parsed as hex**, so a 64-*character* key is not necessarily a 32-byte one. Non-hex padding decodes short and is rejected with `must be 32 bytes (got 1)`.
- Line numbers in `drift-report.md` reflect the 2026-07-31 tree — verify before citing.

## Bridge index — the named cross-package handoffs

The current seams. Reach for them before grepping. They may move, merge, or change signature as long as ownership and dependency direction hold.

**Data → API**
- `$setAuth(user)` / `asSystem()` — the Data-boundary checkpoint / bypass — `litestone/src/core/client.js`
- `withLitestoneDb(db)` — per-request scoped client on `ctx.locals.db`; auto-installed by `createApp({ db })` — `junction/src/core/litestone.ts`
- `gateAuth()` + `autoValidate()` — schema-derived 401s/400s for model services — `junction/src/core/litestone.ts` + `core/service.ts`
- `sessionGateLevel(user)` — `SessionContext` → litestone's 0–7 scale; pass to `GatePlugin({ getLevel })`. Litestone's own default grades a shape Junction does not produce
- `toDataPrincipal(user)` — the OTHER half of the same translation: `SessionContext` → the principal litestone's `auth()` reads (`userId` → `id`). Applied at both `$setAuth` call sites. Without it every row policy matches nothing and nothing says so
- `accessorCandidates()` — `model Post` ⇄ service `posts` ⇄ `db.post`; shared by query, gate and validation so a naming slip can't disable just one

**Schema → API/UI**
- `generateJsonSchema(schema)` — consumed by junction validation and sierra's `build/schema-plugin.js` → `registerSchemas(defs, modelNames)`. **`$defs` is the whole definition table** (models, enums, `type T`, FileRef) and must stay whole — enum fields emit `{"$ref":"#/$defs/Plan"}` and both sides resolve it. Model names travel separately
- `@label` → `title` and validator messages → **`x-messages`**, keyed by rule name *and* by the JSON Schema keyword it compiles to. Litestone owns the keyword table (`jsonschema.js`); Junction's `schema.ts` and Sierra's `field-rules.js` each just look up the keyword they failed. A field's label is read off the field's OWN schema, never a `$ref` target — enum `$def`s are titled with the type name
- `buildFieldRules()` / `validateAgainstFields()` / `coerceToSchema()` / `normalizeBlanks()` — `sierra/src/junction/field-rules.js`, deliberately a **leaf module** with no Junction-client import, so it runs in plain Node and can be compared against junction's server rules rather than a copy. Pipeline order is **coerce → blankToNull → validate**. All three ON by default on `createResource` as of 2026-08-06 (`{ validate: false }` opts out; the test is `!== false`, so a threaded-through `undefined` does not disarm it)
- `toFieldErrors(err)` — same module, also `resource.fieldErrors(err)`. **The one owner of "a thrown value → per-field messages."** Three shapes reach it because each hop wraps once: `err.errors` (ResourceValidationError), `err.data.data` (a server 400 through the browser client — the double `data` is real, both transports produce it), `err.data` (one shallower). Returns `{ fields, message }`; `message` is empty when the failure was entirely per-field. `@frontierjs/ui`'s `<Form>` calls it and knows nothing else about error shapes
- `$context.form` — **the UI-side form seam**, provided by `ui/components/forms/Form.mesa` as `{ errors, submitting, disabled, fields, submitted }`. Nine controls consume it to resolve their own label, constraints, `aria-invalid` and message; an absent form reads `undefined` and every fallback is what the control did standing alone. A stated prop always wins, including `required={false}`
- `buildRelations()` / `buildGate()` / `canAtLevel()` — same module. **`x-relations` is the only place a relation exists on the client**; `x-gate` is an affordance, never a boundary
- **`x-version`** — names the `@version` column an update must carry back, plus `readOnly` on that field in the update schema and absent from the create schema. `buildVersion()` reads it; `createResource` remembers the version of every record it reads and puts it on the next patch, so an app writes nothing. A stated version still wins. `resource.version(id)` / `.versionField` expose it
- **`retryable` on a thrown error** — the one thing a status cannot carry. A 409 is a race (`VersionConflictError`, `TransitionConflictError` — re-read and re-apply) or a domain refusal (`TransitionViolationError` — show its own message), and only the flag separates them. Set it on any error class you own; `toFrameworkError` adopts it and `FrameworkError.toJSON` puts it on the wire, where both transports land it at `err.data.retryable`. `isStaleWrite(err)` is the client-side reader and `toFieldErrors` turns a true into a sentence
- `buildTransitions()` / `transitionsAt()` — same module. `@@transitions` reaches the client as **`x-transitions` on the model, keyed by field** — never on the enum `$def`, because only a model can carry a per-transition `@gate` and two sources would drift. Mirrors litestone's `db.<model>.transitions(row)` field for field; `allowed` is an affordance on the same permissive contract as `canAtLevel()`
- `modelNameFor()` / `schemaFor()` — `sierra/src/junction/schema-registry.js`. Regular English plurals only; irregulars need `createResource('people', { model: 'Person' })`. A miss warns and degrades to a bare `make()`
- `authSchemaFragments(db)` — auth contributes INTO the seed — `auth/schema.ts`. The CLI's `auth/install.md` is a hand-copy: change one, change both

**API internals**
- `bridge.toContext()` / `toResponse()` — the transport↔service boundary — `junction/src/transport/bridge.ts`
- `toFrameworkError()` — the error boundary. Order: `FrameworkError` → `registerErrorMapper(fn)` → numeric `status`/`statusCode`/`code` in 400–599 → `err.name` → 500. **If you own the error class, give it a `status`** — no registration, no Junction dependency. `registerErrorMapper` is for errors you can't modify
- `wrapResult()` / `unwrapResult()` / `isServiceResult()` — the result envelope. `kind:'single'|'list'` discriminates; a list keeps its envelope, a single unwraps
- `ctx.directives` — parsed from `$`-params by the bridge and nothing else
- Plugin protocol `{ name, register, boot, ready, shutdown, requires }` — `junction/src/core/app.ts`. **`register` is sync** (`configure()` never awaits it) — async setup goes in `boot()`. `requires: ['mailer']` is checked once at startup against presence *and* configure order
- `runStartPhases(bindHost)` — the one startup list; `needsHost` phases are skipped by the test path
- `IAuth.verifySession(token)` — inbound auth — declared `junction/src/auth/types.ts`, implemented `auth/auth.ts`
- `manifestPlugin()` + litestone `status()` — migration state into `/manifest`

**API → UI**
- `publish()` hook + `app.channel(name)` — real-time — `junction/src/transport/channels.ts`. Services declare `channel: 'posts'`; `callService` is the single announcement point for both the bus (`svc:created`) and channels (`svc created`). **A custom action announces too, under its own name** (`orders pay`) as of 2026-08-06 — it did not until then, so an action changed a row and told nobody, and every app masked it by refetching after the call. Only `find`/`get` are excluded; a read-shaped action opts out with `ctx.dispatch = false`. Open: litestone `onEvent` has no Junction subscriber; jetty hardcodes Feathers-style names
- **Transport: WebSocket is the default when one is connected, HTTP is the fallback.** Every service call — CRUD *and* custom actions — checks `_wsReady` first; over WS it is a `service_call` frame naming the method, over HTTP it is the REST verb (custom actions: `POST /{service}/{id}` + `X-Service-Method`). The one documented exception is a payload carrying a File: multipart cannot travel over the socket. Stated in `junction/README.md`; `action`/`restore` ignored it until 2026-08-04
- `createJunctionClient()` / `client.resource(name)` — `junction/src/client/index.ts`, consumed at `sierra/src/junction/index.js`

**UI**
- `watchProxy()` / `createSignal()` / `createRoot(fn)` — the reactive seam and lifetime ownership — `mesa/runtime.js`
- `mount(label, Component, {props, root})` — page entry. Registers the delegation root; a component called directly renders but handles no events
- `renderComponent(src, opts)` — UI → HTML at build time; Sierra's `static` target composes route + layout chain through it. Children must be supplied **both** ways (`children={s}` and element children) — the two slot protocols don't bridge
- `island(anchor, Comp, props, block, meta)` — the island seam, off by default. Markers are **comments, not an element** (an element is foster-parented out of `<tbody>` and joins `>` selectors). Sierra collects them at prerender, bundles one chunk per island, and mounts via `@frontierjs/sierra/islands`. **A mounted ancestor is authoritative** — nested islands render live before their directives fire; test a marker with `isConnected`, not `parentNode`
- `externalSignals` — sierra tells mesa which imports are reactive — `sierra/src/build/mesa-plugin.js`. Hand-maintained; slated for retirement

- Auth developer-facing API. `/auth/*` intentionally bypasses the Service abstraction (login can't be gated by login)
