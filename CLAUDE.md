# FrontierJS — Map

Bun-workspace monorepo: a schema-seeded fullstack framework. One mental model — three realms, three nouns:
**Data (Model) → API (Service) → UI (Resource)**, plus Deployment (Release) and Testing (Suite).
Everything derives from `db/schema.lite`; growth happens outward and traces back.
The vocabulary in `ARCHITECT.md` §2 is mandatory when describing or designing anything here.
Model names are **PascalCase and singular — always** (`model Lead` → accessor `db.lead`); `@@external` models exempt (they mirror foreign tables).

Before changing behavior that looks odd, check `DECISIONS.md` — several semantics are deliberate rulings, not bugs.

## Dependency direction

`Litestone ← Junction ← Sierra` — never the reverse. Mesa is a leaf consumed by Sierra and jetty.
Caveat: this direction is wired by optional peer-deps, dynamic imports, duck-typing, and hand-copies — **not declared dependencies**. Sierra imports mesa, junction, and litestone and declares none of them (compensated by hand-rolled exports-map resolvers).

## Bridge index — the named cross-package handoffs

These are the actual architecture; reach for them before grepping.

- `$setAuth(user)` / `asSystem()` — the Data-boundary checkpoint / bypass — `packages/litestone/src/core/client.js`
- `withLitestoneDb(db)` — per-request scoped client on `ctx.locals.db`; auto-installed by `createApp({ db })` — `packages/junction/src/core/litestone.ts`
- `gateAuth()` + `autoValidate()` — schema-derived 401s/400s for model services (merged via `createBaseService`; `createService({model})` forwards hooks so the derived layer survives) — `packages/junction/src/core/litestone.ts` + `core/service.ts`
- `generateJsonSchema(schema)` — Data → API/UI; consumed by junction validation and by sierra's `src/build/schema-plugin.js` → `registerSchemas(defs, modelNames)` in `virtual:sierra`. **`$defs` is the whole definition table — models, enums, `type T`, FileRef — not a model list.** Pass the model names separately (sierra takes them from `parseResult.schema.models`); an enum indexed as a model made `createResource('plans')` resolve to it. The table itself must be kept whole, because enum fields are emitted as `{"$ref":"#/$defs/Plan"}` and both sides resolve that ref: junction in `mapProp`, sierra in `resolveRef()` — `packages/sierra/src/junction/schema-registry.js`
- `buildFieldRules(modelDef)` / `validateAgainstFields(fields, data, mode)` — Data → UI field rules and the client-side check, deliberately a **leaf module** (`packages/sierra/src/junction/field-rules.js`) with no import of the Junction client, so it loads in plain Node/Bun and can be compared against junction's server rules directly rather than against a copy. Surfaced as `resource.fields` / `resource.validate()`; `createResource(…, { validate: true })` enforces before create/patch (default off)
- `coerceToSchema(fields, data)` — DOM strings → the schema's declared types, same leaf module. `createResource(…, { coerce: true })` applies it before create/patch (default off). **`el.value` is a string for every control** — `<select>` and `type="number"` included — and Mesa's `bindInput` passes it through unchanged, so a form bound to `make()` sends `"42"` for a Float and fails validation. Never coerces `''` (`Number('')` is 0), never coerces a string that is not cleanly the target type. Pipeline order is **coerce → blankToNull → validate**
- `normalizeBlanks(fields, data)` — `''` → `null` on **nullable** fields only, same leaf module. `createResource(…, { blankToNull: true })` applies it before create/patch (default off), surfaced as `resource.normalize()`. A text input cannot produce "no value", so a form bound to `make()` writes `''` into a nullable column — and SQLite does not agree that those are the same: `String? @unique` takes any number of NULLs but rejects a second `''`, and `WHERE col IS NULL` never matches `''`. Runs BEFORE `validate` so validation judges what is actually sent
- `bridge.toContext()` / `toResponse()` — THE transport↔service boundary — `packages/junction/src/transport/bridge.ts`
- `publish()` hook + `app.channel(name)` — API → UI real-time — `packages/junction/src/transport/channels.ts`
- `createJunctionClient()` / `client.resource(name)` — API → browser — `packages/junction/src/client/index.ts`, consumed at `packages/sierra/src/junction/index.js`
- `watchProxy()` / `createSignal()` — the real Resource→UI reactive seam — `packages/mesa/runtime.js`, used by sierra router/junction and jetty
- `externalSignals` — sierra tells mesa which imports are reactive — `packages/sierra/src/build/mesa-plugin.js` (hand-maintained; slated for retirement per mesa's `PLAIN_OBJECT_STATE.md`)
- `mount(label, Component, {props, root})` — page entry into Mesa — `packages/mesa/runtime.js`. Registers the delegation root; a component called directly renders but handles no events
- `renderComponent(src, opts)` — UI → HTML at build time. Sierra's `static` target composes each route with its layout chain and renders through it — `packages/sierra/src/build/prerender.js` → `packages/mesa/render-component.js` → `render.js`. Children must be supplied BOTH ways (`children={s}` and element children); the two slot protocols do not bridge — see `packages/mesa/STATIC_RENDERING.md`
- `createRoot(fn)` — ownership without tracking, for anything that owns a lifetime (a render, a preview swap). VISION RULE 54 — `packages/mesa/runtime.js`
- `island(anchor, Comp, props, block, meta)` — UI → the client loader, the island seam. Compiling with **`{ islands: true }`** routes a `client:*` call site through it; it wraps the output in `<!--mesa-island {…}-->` … `<!--/mesa-island-->` **in a server render only**, and calls the component directly on a live client. Off by default (VISION RULE 26, amended), and off is byte-identical. Markers are **comments, not a `<mesa-island>` element** — an element is foster-parented out of `<tbody>` and joins `>` selectors, so it would relocate the marker and restyle the page. The marker carries props **as rendered**; `ctx.islands` (flattened onto `renderComponent`'s result as `.islands`, tagged by file) is the compile-time view a bundler needs for name→module. Mount with `mount(openComment, Comp, {props})` — a bare `Comp(anchor, props, null)` renders correctly and registers no delegation root, so the island is inert — `packages/mesa/runtime.js`, emitted from `compiler.js` `makeComponent`. **The loader, per-island bundling and name→module resolution are Sierra's and do not exist yet**; `sierraContext.islandMap` is still consumed nowhere
- `IAuth.verifySession(token)` — the inbound auth bridge — declared `packages/junction/src/auth/types.ts`, called in `transport/http.ts`, implemented `packages/auth/auth.ts`
- `toFrameworkError()` — **THE error boundary**, the single point where a thrown value becomes an HTTP status — `packages/junction/src/core/errors.ts`. Recognition order: `instanceof FrameworkError` → a mapper registered with **`registerErrorMapper(fn)`** → a **numeric `status`/`statusCode`/`code` in 400–599** on the error → `err.name` matching an error class (`NotFound`, `ValidationError`, `AccessDeniedError`, …) → `GeneralError` (500). **If you own the error class, give it a `status` — that needs no registration and no dependency on Junction** (this is how `@frontierjs/auth` and `@frontierjs/caravan` map statuses while importing nothing from junction). Use `registerErrorMapper` only for errors you cannot modify, e.g. a third-party library's. It used to recognise only Junction's own classes plus two Litestone names, so every other package's errors became 500s — that closed world bit auth and caravan independently, and each worked around it differently.
- Plugin protocol `{ name, register, boot, ready, shutdown, requires }` — how caravan/conduit/auth/notifications attach — `packages/junction/src/core/app.ts`. **`register` is `=> void`, not `=> Promise<void>`** — `configure()` runs it synchronously and never awaits it; put async setup in `boot()` (returning a promise warns at runtime and its rejection still aborts `start()`). **`requires: ['mailer']`** declares ordering: checked once at startup before any `boot()`, against both presence *and* configure() order. **`app.provide(name, value)`** is the guarded namespace claim — it assigns the real property (so `AppConduit`/`AppJobs`/`AppNotify` augmentation keeps resolving) but throws if the name is taken, instead of the old silent last-write-wins.
- `authSchemaFragments(db)` — auth contributes INTO the seed — `packages/auth/schema.ts`. The CLI's `auth/install.md` carries a hand-copy: **re-synced 2026-08-01** (it had pre-rename scalars, no `role`/`accountId`, and `@@gate("9…")` — LOCKED, which walls out even `asSystem()`). It is still a copy — change one, change both.
- `parse()` / `parseFile()` — the `.lite` parser everyone reaches for — `packages/litestone/src/core/parser.js` (vscode bundler points at its pre-move path: broken)
- `manifestPlugin()` + litestone `status()` — migration state into `/manifest` — `packages/junction/src/plugins/manifest/index.ts`
- `wrapResult()` / `unwrapResult()` / `isServiceResult()` — THE result envelope, one owner. `kind:'single'|'list'` is the discriminant; a list keeps its envelope, a single unwraps — `packages/junction/src/core/envelope.ts`
- `ctx.directives` — result-shaping (`limit`/`offset`/`orderBy`/`select`/…), parsed from `$`-params by the bridge and by nothing else — `packages/junction/src/transport/bridge.ts` (`parseDirectives`) + `src/core/context.ts`
- `sessionGateLevel(user)` — Junction's `SessionContext` → litestone's 0–7 gate scale; pass to `GatePlugin({ getLevel })`. Litestone's own default grades a shape Junction does not produce — `packages/junction/src/core/litestone.ts`
- `channel: 'posts'` on a service — the declared broadcast target; `callService` is the single announcement point for both `app.events` and channels — `packages/junction/src/core/service.ts` (`publishToChannels`)
- `accessorCandidates()` — `model Post` ⇄ service `posts` ⇄ accessor `db.post`; used by the query, the gate, and validation so a naming slip can't disable one of them — `packages/junction/src/core/litestone.ts`
- `buildRelations(modelDef)` / `buildGate(modelDef)` / `canAtLevel(gate, op, level)` — the last two things the schema carried to the browser and nothing read — `packages/sierra/src/junction/field-rules.js`, surfaced as `resource.relations` / `resource.gate` / `resource.can()`. **`x-relations` is the ONLY place a relation exists on the client** (relations have no wire representation, and implicit m2m was correctly removed from `properties`), so a FK column is knowable as a reference only through it — `buildFieldRules` marks them as `fields.accountId.references`. `x-gate` is a **UI affordance, never a boundary**: unknown answers are permissive, and the server enforces regardless.
- `modelNameFor()` / `schemaFor()` — Sierra's half of the same ⇄, `packages/sierra/src/junction/schema-registry.js`. Regular English plurals only: `-s`, consonant+`y`→`-ies`, sibilant→`-es` (`statuses`→`Status`). **Irregulars are not guessed** — `createResource('people', { model: 'Person' })` is the override, and it covers any service deliberately named unlike its model. A miss is a console warning, not an error, so it degrades to a bare `make()`; the warning now names the fix. `modelNameFor` returns the declared name, which is what makes `ctx.model` the model rather than the service

## Landmines

- **Dialect trap — closed 2026-08-02.** Junction and auth resolve the workspace litestone (`workspace:*` dev-dep + `^1.1.0` peer), so in-repo code gets `Int/String/Float`. Fixing that resolution is also what cleared junction's 7 long-standing "test-drift" failures — they were the dialect mismatch, not drift. **litestone 1.1.0 is now published and npm `latest` points at it** (verified via `npm view` dist-tags and by unpacking the tarball: `SCALARS` carries `Int/String/Float/Bytes`, `RENAMED_TYPES` rejects `Integer/Text/Real/Blob`), so registry consumers get the current dialect too. Still don't pin litestone with a bare `"latest"` or `"*"` range — floating ranges are what let the mismatch happen unnoticed; use `^1.1.0`. Anything installed from the registry *before* 2026-08-02 still has the old dialect and needs a reinstall.
- **Typecheck is wired everywhere (2026-08-01).** Every package has a `tsconfig.json` extending `tsconfig.base.json`, and `bun run typecheck` runs `scripts/typecheck.mjs`. That runner exists because packages import each other's raw `.ts` source, so a bare `tsc --noEmit` reports the *dependency's* errors too (conduit saw 78 of junction's alongside its own). It reports only the package's own diagnostics and takes a `--baseline N` ratchet. Baselines — junction **212**, auth 4, conduit 1, everything else 0 (**caravan's was 7 and notifications' was 8 — both removed, they typecheck clean**). **Lower a baseline when you improve it; never raise one.**
  `checkJs` is off for the JS-first packages (cli, css, jetty, litestone, mesa, sierra) — turning it on today reports 521 / 4,726 / 1,219 / 3,131 / 2,625 / 777 errors respectively. The configs still give editors resolution, and any `.ts` in those packages *is* checked. litestone's `test/**/*.ts` is excluded on purpose: 5 real TS files importing untyped JS source = 1,713 errors under `strict`.
- ~~**`app.conduit` is declared twice**~~ — **fixed 2026-08-02.** Junction now exports an empty `interface AppConduit` and types the field `conduit?: AppConduit` (`src/core/app.ts`); conduit augments *that interface* rather than redeclaring the property. Redeclaring never worked — declaration merging requires identical types, so conduit's augmentation silently lost and `app.conduit` resolved to `{}` at every call site. **If you add another `app.<thing>` from a plugin package, use this pattern, not a property redeclaration.** Junction's baseline dropped 216 → 214.
- **Raw routes (`app.get`/`app.post`) have three traps — all three shipped broken in caravan (fixed 2026-08-02).** (1) Path params are **`{id}`, not `:id`** — `PARAM_PATTERN = /^\{([^}]+)\}$/` in `src/transport/router.ts`, so `:id` registers as a literal static segment and silently 404s forever. (2) `ctx` is `TransportContext`, not a service ctx: `params` is path params only and **headers are on `ctx.headers`**. (3) ~~thrown errors become 500s~~ — **fixed 2026-08-02, see the error boundary below**: a thrown error carrying a numeric `status`/`statusCode`/`code` now maps correctly, so raw routes can just throw.
- **Webhook event matching is `json_each()` equality, never LIKE** (`packages/junction/src/plugins/webhooks/index.ts`). `findForEvent` built a SQL pattern out of the **event name** — `events LIKE ('%"' || ? || '"%')` — so metacharacters in the event name matched other subscriptions: an event named `user_created` was delivered to a hook subscribed only to `userXcreated` (`_` = any char), and an event named `%` fanned out to **every** registration. That is a payload leak — a partner receives correctly-signed data for an event they never subscribed to. Fixed 2026-08-02; don't reintroduce pattern matching on caller-supplied names.
- **`updateDelivery`-style patch helpers must test key presence, not `??`.** With `??`, passing an explicit `null` meant "leave it alone", so nullable columns could never be **cleared** — a webhook delivery that succeeded on retry kept reporting the `HTTP 500` it had recovered from, and kept a stale `next_retry_at`. Use `key in updates ? updates[key] : current`.
- **Startup is ONE named phase list** (`runStartPhases(bindHost)` in `packages/junction/src/core/app.ts`). `start()` and `_startForTest()` both run it; phases flagged `needsHost` (load-config, autoload-services, listen, ready-hooks, signal-handlers, announce) are skipped by the test path. There used to be two hand-maintained sequences numbered 0, 0a, 0b, 0c, 1, 3, 4, 4.5, 4.6, 5, 6, 7, with the test path documented as mirroring "phases 1, 4.5, 4.6" — i.e. a subset that could drift silently. **Add a phase to the list, never to one caller.**
- ~~**`GET /health` 404s while the startup banner advertises it**~~ — **fixed 2026-08-02.** The endpoint was always fine; the *advertisement* was fiction. The banner used `router.hasRoute()`, which asks "would a request for this path **match** something" — and every app registers `GET /{service}`, which matches `/health`. So every app printed a health URL whether or not `healthPlugin()` was configured. **`hasRoute()` is a matching question, not an existence one — use `hasExactRoute(method, path)` when you mean "is this endpoint mounted".** `routePaths(method)` lists where things actually landed; the banner uses it so a health endpoint at a custom path (`healthPlugin({ path: '/internal' })`) is advertised correctly. Also fixed there: `hasRoute(a) ?? hasRoute(b)` never evaluated `b` (`??` only falls through on null/undefined, and it returns a boolean).
- **Router cache: fixed and dynamic routes live in separate fields** (`{ fixed, dynamic }` in `packages/junction/src/transport/router.ts`). They shared one object until 2026-08-02, with dynamic routes under the key `'D'` — so a route registered at **`/D`** normalised to exactly `'D'` and collided: `build()` threw `methodCache.D.push is not a function`, and `lookup()` would have returned the bucket array as if it were a route. Found by a test probing `hasExactRoute`; don't reintroduce a shared keyspace.
- **jetty's `src/resources/` is a hand-copy of sierra's** — already diverged (`createStore` signature). Fix one → audit the other.
- **`mesa-vite/` is nested inside `packages/mesa`** — invisible to the workspace glob; its HMR algorithm is hand-copied into sierra (×2 files) and jetty. It also has **no tests at all**, and its HMR id-normalisation fix has never been confirmed in a browser.
- **`build/` in `.gitignore` was hiding 20 source files** — it matched `packages/*/src/build/`, so Sierra's entire build pipeline and jetty's were untracked and absent from a fresh clone. Fixed 2026-08-02 by un-ignoring the directory; **the 20 files are visible to git but still uncommitted.** If you add an ignore rule, check it against `git status --porcelain` before trusting it.
- **A clean compile does not mean the compiler emitted valid JavaScript.** Three Mesa bugs in 2026-08-02 produced empty `analysis.errors` and a module that threw on load. `packages/mesa/emission.test.js` and `repl.test.js` now check parseability; keep that habit when touching the compiler.
- **Real-time — partly settled (2026-08-02).** Junction now announces a mutation ONCE in `callService` and fans out to both the bus (`svc:created`) and channels (`svc created`); services declare `channel: 'posts'`. Still open: litestone `onEvent` has zero Junction subscribers (needs a post-construction subscribe in litestone, mirroring `$tapQuery`), and jetty hardcodes Feathers-style event names.
- **Audit logger writes 0 rows** in litestone's examples (`@@log(audit)` → logger driver) — pre-existing, cause unknown (async flush suspected).
- Line numbers in `drift-report.md` reflect the 2026-07-31 tree; verify before citing.

## Unsettled (ARCHITECT.md §5, corrected)

- Auth developer-facing API not finalized; auth's `/auth/*` routes intentionally bypass the Service abstraction (login can't be gated by login).
- Custom service methods: called `actions`; name under review; dispatch stays via `X-Service-Method` header (decided — see DECISIONS.md). ~~Live bug: `/metrics` reads a nonexistent `svc.actions` key~~ — **fixed 2026-08-02**: `/metrics` now uses `customMethodNames()`, the same predicate as manifest and OpenAPI (`svc.allowBulk` was misreported the same way and is also fixed).
- Multi-tenancy = db-per-tenant only (litestone `createTenantRegistry`); config API under design.
- Hook context shape differs across realms; junction's split (`auth`/`client`/`route`/`locals`, plus `query`/`directives`) is the candidate standard.
- UI plugin system limited; JSON Schema → UI drives `make()` only.
- ~~Query params: `$limit`/`$offset` at API vs `limit`/`offset` in litestone~~ — **settled 2026-08-02**: `$` is transport syntax only. `ctx.query` is filters, `ctx.directives` is `{limit, offset, orderBy, select, …}`, and nothing past the bridge sees a `$`. See DECISIONS.md.
