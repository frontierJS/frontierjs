# FrontierJS — Map

Bun-workspace monorepo: a schema-seeded fullstack framework. One mental model — three realms, three nouns:
**Data (Model) → API (Service) → UI (Resource)**, plus Deployment (Release) and Testing (Suite).
Everything derives from `db/schema.lite`; growth happens outward and traces back.

`ARCHITECT.md` §2 is the default vocabulary for design discussion. Depart from it when a different word is materially clearer — then fold the clearer word back in rather than keeping two.

## Evolution policy

FrontierJS is pre-alpha. **Prefer evolving existing designs over preserving them.** Existing behavior is evidence, not a constraint.

Only two things are binding: the **Invariants** below, and rulings in `DECISIONS.md`. Everything else may change — prefer simplifying, removing duplication, and improving consistency over reproducing what is there. **Preserve the mental model, not the mechanism.**

**A change that turns on a judgment call runs `decision-rules`** (`.claude/skills/`) — `PHILOSOPHY.md` § V's nine questions against the proposal, § IV where two goods are in tension, § VII for which kind of document may hold the answer. It fires on the ACT rather than on the doubt: adding an option, coining a noun, restating something already stated, choosing between two designs, or finding the code and a document disagree.

Where docs disagree, assume different stages of a pre-alpha design and reconcile, rather than treating either as wrong.

**This file is only what is live.** History belongs in `packages/*/CHANGES.md`, open defects in `ISSUES.md`, settled arguments in `DECISIONS.md`. A line here earns its place by changing what someone does in the next hour.

## Invariants

Don't violate without an explicit decision; record it in `DECISIONS.md` if you do.

1. **Dependency direction** — `Litestone ← Junction ← Sierra`, never reverse.
2. **Model names are PascalCase singular** (`model Lead` → `db.lead`); `@@external` exempt. Three resolvers depend on this agreeing.
3. **App layout** — `db/` at the root and each SURFACE a directory beside it: `api/`, `web/`, `site/` (the public prerendered site), `widgets/` (embeddable scripts) and `extension/` (a jetty browser extension). Most sub-projects carry `config/ src/ public/ test/ dist/ deploy/` (db/ doesn't). Configuration lives in `config/`, `vite.config.js` included. Which surfaces an app has is the app's business — api-only, web-only, **site-only**, **widgets-only** and **extension-only** are all whole projects — but a surface inside another one is not: folded into `web/`, it inherits the SPA's build, port and release. A surface earns its own directory when its config, its tests and its release are all different answers, which is what `site/`, `widgets/` and `extension/` are. **`site/` has a fourth and it is the decisive one — OUTPUT**: one Vite root is one `dist/`, and `vite build` empties `outDir`, so a `target: 'static'` site living inside `web/` is deleted by the next SPA build with nothing said (`FJS-D127`, `FJS-449`). `fli check`'s `app-layout` reports a static config found inside another surface. Canonical: root `README.md` §Project Structure. Never *derive* a config path from where `vite.config.js` sits — probe, or be told.
4. **One owner per translation.** Exactly one place turns a thrown value into an HTTP status, one wraps/unwraps the result envelope, one parses `$`-params into `ctx.directives`, one announces a mutation, one startup phase list every caller runs. Implementations are in §Bridge index. Add to the owner, never beside it.
5. **One owner per `app.<thing>`.** Claim it with `app.claim(name, value)`; type it by augmenting an exported interface, never by redeclaring the property — declaration merging requires identical types, so a redeclaration silently loses. The verb is `claim` and not `provide` because **a Provider is a third party the app speaks to** (`FJS-D06`) — `/metrics` contributions go through `app.registerMetricsSource(name, fn)` for the same reason.
6. **Access is declared in the schema, not in hooks.** Gates, `@encrypted`, `@guarded`, `@@transitions` are enforced at the Data boundary. `x-gate` on the client is a UI affordance only — unknown answers are permissive and the server enforces regardless. No exceptions.
7. **Protected fields are redacted in the audit trail.** `@encrypted`/`@guarded`/`@secret` log as `[redacted]` in field entries and in `before`/`after` snapshots.
8. **Caller-supplied names never enter a SQL pattern.**
9. **Patch semantics: an explicit `null` clears.** Test key presence (`key in updates`), not `??`.
10. **A `$`-PREFIXED KEY is transport syntax only.** `$limit`, `$offset`, `$orderBy`, `$select` are how a directive travels on a wire; `ctx.query` is filters, `ctx.directives` is `{limit, offset, orderBy, select}`, and no `$`-prefixed KEY survives the bridge. The rule is about the prefix on a parameter name and about nothing else — junction's ambient `$`, the service call in progress, is a different thing that happens to share a character (Bridge index § API internals). **Two boundaries read the convention** — junction's bridge off a request, sierra's router off a URL onto `page.query` + `page.directives` — and the table they read it by is one module, `@frontierjs/toolbelt/directives`, one row per directive so a Data-realm feature that grows a per-call option cannot arrive half wired. **What the VALUES mean is the sibling module, `@frontierjs/toolbelt/query`** (`FJS-D125`) — a string is a number only if `String(Number(v)) === v`, `true`/`false`/`null` are themselves, structure is bracket notation, and `?code="5"` is the escape. Three readers: junction's transport, junction's client writing one, sierra's router. **Not a WS frame**, which is JSON and already carries its types.
11. **The nearest delegation root owns an event.** Roots nest; a handler must fire once.
12. **Mesa compiler output is reproducible** — scope ids are content-addressed, which is what makes CSS dedupe work across the two compilers a static build runs.
13. **`@frontierjs/css` is the styling language.** Style with a tone (`danger`) and a treatment (`outlined`), never a color. UnoCSS is supported *alongside* it as an opt-in layer a consuming app configures (`packages/css/README.md` §Using it with UnoCSS). A package in this repo ships no utility classes — a component needing Uno to look right is unusable by an app that does not run it.
14. **Typecheck baselines ratchet down only.** `scripts/typecheck-baselines.json`, one number per package; absent means 0. `bun run typecheck -- --update` writes an improvement back.
15. **A clean compile is not proof of valid JS.** Compiler tests parse their output.
16. **Runnable examples are verified, not sketches.** A broken one is a bug.
17. **Four markdown files at a package root is the standard** — `README.md`, `CLAUDE.md`, `PROJECT_STATE.md`, `CHANGES.md`; everything else in `<pkg>/docs/`. **`AGENTS.md` is a permitted fifth and is not required** (`FJS-D163`): it is the same KIND of thing as `CLAUDE.md` — a root document whose whole value is being findable at the root, under the name other tools converged on — but it addresses a CONSUMER of the package rather than a contributor to it, so a package nobody writes against does not owe one, and the two are not folded because one audience has the source and the other has a tarball. **It only reaches that audience if `files:` ships it**, which is decidable from `exports.snapshot.md` and was false for litestone until it shipped one. **A sixth is a question, not a refusal**: `package-root-md` warns and names it, because the rule cannot tell a stray design note from the next thing everyone needs at the root. Answer it — move the file, or record an allowance saying why it stays. Generated `*.snapshot.md` is exempt; it is gated output, not documentation.
18. **In a Sierra app, `src/resources/` holds `.mesa` files, and a resource file carries its model's default form.** A Resource is a UI-realm noun, written in the UI-realm language. The data half is `<script module>` — `createResource` and the model's own verbs — which runs once at import and is what every other module imports (Mesa VISION §11, rule 30); that half is required. **The markup half is the form and it is optional**: with it, a create or edit page is `<Order />` and nothing else, and a page wanting a different form passes children, which `<Form>` already lets win. A file with no `<script module>` is a component in the wrong folder (`FJS-D112`).
19. **A resource file is named for its noun — PascalCase, singular — one Resource per file.** `App.mesa` exporting `export const apps`; the same split the Data realm makes between `model App` and `db.app`. Where a model exists the filename IS the model name, so an irregular is visible (`AlertRule.mesa` exporting `alerts` says `model:` must be stated). A resource over no model takes its service noun, singularised.

## Running things

**Always `cd` into the package and run its own script.** Runners differ per package and a wrong runner produces failures that belong to nothing. `bun run --filter '*' test` from the root runs them all, one each. `bun test` instead of `bun run test` runs bun's own runner over whatever it finds — in mesa that is ~35 failures that are runner artifacts.

**`bun run ci` is the whole of CI and it is not a GitHub feature.** One node script runs thirteen phases and `.github/workflows/ci.yml` does nothing but call it, so it runs identically on a laptop. `ci:fast` skips the suites, `--only <pkg>` narrows typecheck and tests, and `bun run hooks:install` points `core.hooksPath` at `scripts/hooks`, whose `pre-push` runs the fast tier — the suites belong in the workflow, because a pre-push costing minutes teaches everyone `--no-verify`. Every allowance is a named entry with a reason in `scripts/ci-allowances.json`.

| Phase | What fails it |
| ----- | -------------- |
| `hygiene` | a source file `.gitignore` hides, and **a dependency or a clock inside the substrate package** — `@frontierjs/toolbelt` may be imported by litestone and mesa only because it depends on nothing, so a non-relative import under its `src/` fails the build |
| `structure` | an architecture rule broken in this repo's own apps. It runs `packages/cli/core/checks.js`, the same engine `fli check` gives a client app, because two implementations of one rule is how a framework ends up breaking rules it publishes |
| `registers` | an id a register issued twice, a citation pointing at nothing, a ruling nobody named — `packages/cli/core/register-check.js`, the engine behind `fli register:check` |
| `snapshots` | a committed `*.snapshot.*` that no longer matches its source. It carries **no list of what exists**: every snapshot names the command that wrote it in its own header, and that command is rerun with `--check` from the file's own directory, so a new KIND of snapshot costs a generator and never a CI edit. The command comes out of a file in the repo, so it is restricted to a known binary and a shell-free argv, and a snapshot naming no generator fails rather than being skipped. **Discovery alone fails open**, so the expectation comes from the BASE REF — a snapshot tracked where the branch left main and absent now is a failure, because a generated artefact that stops existing takes its check with it in green. A deliberate removal is a named entry under `removedSnapshots` |
| `access` | nothing, by design. **The one phase that reports rather than judges** — *what did this branch do to who may do what*, printed per app against the base ref — because a branch that widens access is usually a branch doing its job, and a red that fires on every feature trains everyone to skip the phase. The gate is `fli test:access --from <ref> --strict`, which belongs on the branch that deploys |
| `coverage` | a package with no `test` script that `exemptPackages` does not name |
| `registry` | a `@frontierjs` package `fli new` writes into an app's `package.json` that npm has never heard of. **It asks the half the register cannot see**: every id there is a statement about the WORKING TREE, and a user's experience is the tree AND the registry, which drift independently. The list is read from `core/app-config.js`, the module `fli new` itself reads. A version gap is a NOTE; an unpublished package is allowed by name under `knownUnpublished`, which fails once it IS published; no network is a named skip that `FJS_CI_REQUIRE_REGISTRY=1` makes fatal |
| `advisories` | an advised package **reachable from a PUBLISHED package's runtime `dependencies`**, since that is the set every app installs — walked from each package's own directory and resolved the way node resolves, because bun installs into `.bun/` with symlinks and a path guess reports every advisory as dev-only. A **comparison rather than a scan**: a vitest advisory is not something an app installing this framework can be hurt by. The resolved version is printed beside the advisory's range and **the two are never compared**, because a range parser here would be a security judgement made by a regex. `knownAdvisories` is the named allowance; `FJS_CI_REQUIRE_AUDIT=1` makes a no-network skip fatal |
| `scaffold` | **the phase no suite can replace.** It packs every publishable package, scaffolds an app against the tarballs, installs it, builds it, runs that app's own `bun run check`, then scaffolds a model into it and builds again, and finally writes a `site/` surface into it and builds THAT (`scripts/scaffold-build.mjs`) — a second Vite root with its own config, its own entry and its own prerender pass, none of which the SPA build reaches, and every file of which was broken for as long as nothing ran one (`FJS-758`). An app in this repo resolves sierra to `packages/sierra/` and never to a node_modules path, so the code that only runs for an *installed* app runs nowhere else here. It grades each package's `files:` field for free, and **its per-run `--cache-dir` is load-bearing**: bun caches a tarball by name *and* version, so a shared cache serves the previous run's bytes and the phase passes against a broken tree |
| `typecheck` | a *raised* baseline (Invariant 14) |
| `deploy` | the pipeline an app actually deploys with, in two halves. `fli new` → `make:deploy` → `deploy:local` **once per package source**, each ending in a **register and login through the prefix the app's own `web/config/sierra.config.js` names**, because a health answer says the process is up and not that the app works. `--source npm` is the only thing here testing the PUBLISHED framework; `--source local` is the working tree containerised, which needs `core/vendor.js` to pack the tree into the build context, since a Docker build can see neither a `link:` spec nor a tarball outside it. The second half is **`deployJournalCycle`, the only thing that runs `fli deploy`** — deploy → deploy → crash → resume → revert, an unbound attachment, a declared binding key nothing carries, and the build a browser compares against, all against `localhost` as a real deploy machine with real docker, a real journal and a real revert. `core/machine.js` is the one owner of *(host, script) → the argv that runs it there*, and the script travels on **stdin** to `sh -s`, so the same script reaches the same shell with or without an ssh prefix; the only thing it does not exercise is ssh itself. Its sharpest assertion is that an unchanged redeploy mints the SAME Release. Full tier only. Without a daemon it reports a named note and passes, and `FJS_CI_REQUIRE_DOCKER=1` turns that skip into a failure, which the workflow sets; `knownDeployFailures` exists for publish order, where the scaffold gives an app a package nobody has published |
| `tutor` | a command renamed out from under a lesson, a scaffold whose default gate moved, an answer the framework changed. It **executes the tutorial** — thirteen lessons, `--tmp --yes`, on test-tier ports, each lesson a command whose every step ends in a probe against the running world rather than an exit code: a port that answers, a table in `sqlite_master`, a row read back out of the file the app wrote, the same POST answered 201 with a token and 401 without. It is the phase for the one document that had no compiler behind it. A port already held is a SKIP rather than a finding, because the lessons refuse a busy port rather than moving to the next one; `knownTutorFailures` is the ratcheting allowance |
| `tests` | a suite. A suite known to fail is named, so a NEW failure is loud |

**The browser drives need their servers started by hand, first.** They exit 1 naming the missing process. All need Chrome. **The *Start first* column is READ** — `packages/cli/core/preflight.js` parses it, `runnables.js` puts the resolved steps on the drive's row, and `fli gui` walks them behind one button, skipping anything already answering. So the order in a cell is the order they are run in, `nothing` is the explicit empty answer rather than a blank, prose after the em-dash is not read, and a step whose script has been renamed is a `fli check` error (`drive-preamble`) rather than advice somebody notices is wrong. What it cannot see is the drive's own check, which is the half `--preflight` would close.

## House style

Match the file you are in first; this is what the repo does when there is no local precedent.

- **Comments explain the failure, not the mechanism.** `// increment the counter` is noise; `// vite hops ports silently, so the drive would talk to the other app` is the house voice.
- **A comment must be load-bearing. Delete it otherwise.** Test: if it vanished, could someone editing this file make a mistake it would have prevented?
  - **No edit history in code** ("used to be", "this replaced X", "merged 2026-08-08"). That is `CHANGES.md`, `DECISIONS.md` and git. Narrow exception: a past bug stated because the shape still invites it (`--ring` in `tokens.css`), where the history IS the warning.
  - **No dates in code comments.** If the comment needs one, it belongs in a decision record the code points at.
  - **No persuasion** — "the whole point", "deliberately", "which is exactly why", italics for emphasis. State the constraint flatly; if it needs selling, it needs a ruling.
  - **Never narrate your own edit.** The reader does not know a change happened.
- **Never put a backtick in a comment inside a template literal.** A SQL schema, an nginx config and a shell script are all written as one here, and a comment quoting `an identifier` closes the literal — the file then fails to PARSE, so the failure is nothing to do with what the comment says and points at a line further down. Twice in one day: `packages/caravan/src/db.ts` (every `bun run api` and therefore every drive) and the nginx deploy template (the cli suite). Use plain words or `--` quoting; the cli's *every shipped command compiles to parseable JS* test is the only thing that catches it, and it only covers `commands/`.
- **Every non-trivial file opens with a header block** — what it is, and what it is for. Test harnesses document their own traps at the top (`example/web/test/verify.mjs`).
- **Section dividers inside a file**: `// ─── name ──────` (box-drawing, padded to a consistent width). Not `// ---`, not banner boxes.
- **Aligned columns** where a run of lines is parallel — imports, object literals, `const` blocks. See `example/api/src/app.ts`.
- **Prose in the docs is sentence-shaped, not bullet-shrapnel.** Bold the claim, then say what it cost. Numbers earn their place by being measured.
- **A document an agent reads is written by `doc-hygiene`** (`.claude/skills/`) — the two loads it spends, the ladder from in-file step down to disclosed reference, and the four cuts (the delete test, cache, negation, sprawl). Reach for it before adding to a `CLAUDE.md`, a `SKILL.md`, or anything reached by a pointer. **A section a parser reads cannot move**: six modules read this file by path, and relocating one of those tables is editing a parser.
- **American spelling** throughout, prose and identifiers alike (`behavior`, `serialize`, `color`) — flipped from British in `FJS-D192` (see `DECISIONS.md`), `example`'s `ProductVariant.colour` renamed to `color` along with it since nothing here has ever been deployed. One exception remains: `cancelled`, a persisted enum value on several `@@transitions` models across `example` and `basecamp` — renaming a value already written to a running app's database is a migration, not a find/replace, and nobody asked for that one yet.
- **No semicolons**, single quotes, 2-space indent, in TS and JS alike (`packages/css`'s own build/test scripts are the one holdout). TypeScript in junction, auth, caravan, conduit, notifications; plain ESM JavaScript in litestone, mesa, sierra, ui, css, jetty. Do not introduce TS into a JS package.
- **Fake clients hide real bugs.** Cross-package behavior is tested against the real dependency — `{ post: {…} }` passed every test and failed every real Litestone client.
- **A new `on*` states its tier** (`FJS-D06` §1) — **Hook** may mutate the arguments or halt the operation, **Guard** answers allow/deny, **Observer** receives and cannot act. The word goes on the option that holds it: conduit's callbacks are `observers:` because a throw in one is swallowed, and `management.hooks` beside it keeps *hook* because that pipeline can refuse the call.
- **A new defect gets an `FJS-###` in `ISSUES.md`**, not a paragraph in a package file. A ruling closes an `FJS-D##` and moves to `DECISIONS.md`. Check a new `.gitignore` rule against `git status --porcelain` — an ignore glob hid twenty source files once.

## Live hazards

**Correct behavior you have to know about.** Things that are *wrong* live in `ISSUES.md`, one id each; things that are *fixed* live in `CHANGES.md`. If a rule here is pinned by a test that cannot be deleted quietly, it does not need to be here.

**The three realm catalogues are skills rather than sections** (`.claude/skills/`). A trap about `@@softDelete` costs nothing on a turn spent in sierra and everything on the turn it is needed, so each fires on its own realm and is otherwise the document it was here. | UI | `ui-hazards` | mesa · sierra · a `.mesa` file · a resource · a form · a live store · prerender · islands · `@frontierjs/css` |

**Repo** stays here, because it belongs to no realm.

- **`bun install` resolves `workspace:*` to a COPY under `node_modules/.bun/`, not a symlink.** An edit to `packages/mesa/src/compiler.js` is invisible to importers until reinstall, so a suite can go green against a stale snapshot. In-repo tests import workspace source by relative path. `packages/ui`'s hand-made symlink will not survive a reinstall.
- **Nested directories are invisible to the `packages/*` glob** — uninstalled, untested, unrunnable. Four cases, all deliberate and named in `scripts/ci-allowances.json` § nonMembers: `mesa/mesa-bench`, `oracle/mockup`, `orion/mockup/api-engine`, `toolbelt/mockup/datetime`. **A fifth is a CI note naming the path**, so the way this goes wrong is by someone reading the note as noise, not by silence.
- **Publishing a package silences every loose peer range that names it.** While a sibling is unpublished a peer of `"*"` fails at install with the name in the error; the moment it exists, the same range resolves from the registry without a word. **Below 1.0 a caret pins the MINOR** — `^0.1.0` is `>=0.1.0 <0.2.0` — which is both the behavior wanted for a pre-alpha peer and the trap in the other direction, where a stale caret excludes the only published copies. Nothing catches either shape from inside the workspace: a `workspace:*` devDep answers first and the range is never consulted. **`fli ws:exports` commits the published surface** — `exports.snapshot.md` at the root, one section per publishable package: the top-level entries its tarball actually contains (asked of `bun pm pack --dry-run`, never derived from the globs), every `exports`/`bin`/`main`/`types` target marked with whether that tarball holds it, and the peer ranges naming a sibling. A declared entry point `files:` does not publish is a broken install, decidable from the listing alone. The `snapshots` CI phase fails a stale one.
