# Issues — archive

**Closed items, moved out of `ISSUES.md` so the register stays the list of what
is live.** Nothing here is open. Ids are never reused and never renumbered, so a
`FJS-###` named anywhere in the repo resolves either there or here.

**When a row moves.** `ISSUES.md` § Closed keeps the most recent closures and is
trimmed when it passes ~40 rows. A count rule rather than an age rule, because
closures arrive in bursts — 37 of these were closed on one day, and a date rule
alone lets one busy day bury a month. Everything older comes here, copied
verbatim: a row is never rewritten or summarised on the way in.

**Why keep them at all.** The same reason § Closed exists: a stale document, an
old handoff, or a comment in code can name an id and imply it is still broken.
This is how that gets refuted with the evidence attached — what the defect was,
what changed, and how it was proven. It is also the record of what building each
package actually cost, which no single changelog carries.

Read it when tracing something specific, never cold. `ISSUES.md` is the file
that answers *what is wrong right now*.
